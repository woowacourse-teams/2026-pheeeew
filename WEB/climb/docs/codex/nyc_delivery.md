# NYC 빌딩 숲 에셋 납품

## 저장 결과

- `public/assets/nyc/`: rock, fabric, trim, bg, arrow_sign 5장.
- `public/assets/nyc/kit/`: top 6장, hang 5장, side 4장, in 6장, far 3장. 합계 29장.
- `docs/codex/check_nyc.png`: 1440×1000 합성 확인 그림. 지형 덩어리는 정확히 900×300px, 재질·장식·원경·표지판은 50% 크기, 캐릭터는 폭 75px.
- `docs/codex/nyc_contact_sheet.png`: 24개 kit 에셋과 투명도 확인용 모음.
- `docs/codex/nyc_tile_{rock,fabric,trim,bg}.png`: 각각 2×2, 2×2, 3×1, 1×2 반복 확인 그림.

## 판단과 수정

- 내장 `image_gen`으로 각 에셋을 개별 생성했다. 에어컨과 현수교 주변의 넓은 밝은 배경막은 같은 도구로 제거했다. CLI/API 생성은 사용하지 않았다.
- 캐릭터가 먼저 보이도록 벽돌 평균색을 약 RGB(165,119,111)의 저채도 벽돌색으로 낮췄다. 창문 불빛은 부드러운 노랑 포인트로 남겼다.
- top y=200, hang y=56, side x=56에 노출부를 배치하고, 묻히는 방향은 실제 rock 평균색에서 alpha 0으로 사라지도록 정규화했다. 장식의 물체 자체 색은 보존했다.
- 창문 네 장은 외곽 150×190px 규격이며 같은 기준 창틀의 픽셀을 공유한다. 유리 안쪽만 불 켜짐/꺼짐/커튼/고양이로 구분된다.
- 생성 차양의 실제 줄무늬 주기를 측정해 잘랐다. 첫 반복 검수에서 발견한 경계 꺾임을 반대편 여백의 같은 방향 샘플로 연결해 제거했다.
- 원경은 흐릿한 분홍·보라색 반투명 실루엣으로 정리했다. 지형 외곽선 #3b2a2e는 확인 그림에만 그렸으며 재질에는 넣지 않았다.
- 캐릭터는 lineup의 첫 번째 tired 캐릭터와 동일한 `refs/tired/front.png` 투명 원본을 사용했다. 두 원본의 불투명 캐릭터 픽셀 평균 채널 차이는 0.0013/255로 확인했다. 그림이나 비율을 다시 생성하지 않았다.

## 검증

- 합성 그림, 전체 kit 모음, 재질 2×2, 코니스 3회, 배경 2회 반복을 직접 열어 확인했다.
- 29장의 지정 크기와 알파 검사 통과. rock/fabric/bg는 모든 픽셀 alpha=255. kit 및 표지판 캔버스 외곽은 alpha=0.
- rock/fabric 상하좌우, trim 좌우, bg 상하의 맞닿는 가장자리 픽셀 최대 차이 0.
- top 노출 높이 37~67px, hang 길이 87~152px, side 돌출 길이 77~103px. 기준선 연결과 지형 안쪽 알파의 단조 감소를 확인했다.
- trim y=40 전체가 연결되고, 가장 높은 불투명 부분은 y=20~40 범위 안이다. 아래쪽은 불규칙한 길이로 투명해진다.
- 창문 네 장의 공통 창틀 픽셀 최대 차이 0. 표지판 폭과 바닥 (256,450) 검사 통과. 화살표는 오른쪽 위를 가리킨다.
- 기존 파일 169개 해시를 추적했다. 기존 PNG는 모두 동일하다. 작업 중 `public/main.js`, `public/rig.js`의 해시 변화가 관찰됐지만 이 작업의 쓰기 대상이 아니며 수정하거나 되돌리지 않았다.
- 검증 범위는 에셋과 요청된 합성 그림이다. 게임 JavaScript 변경 및 실제 게임 연결은 수행하지 않았다.

## 재현 자료

- 생성 및 수정 프롬프트: `nyc_work/prompts.json`
- 선택한 원본 경로: `nyc_work/sources.json`
- 파일·픽셀 검사: `nyc_work/validation.json`
- 합성 배치 좌표: `nyc_work/placements.json`
- 재생성: `node tools/prepare_nyc.cjs`
- 검사: `node tools/verify_nyc.cjs`

이미지 생성 도구의 자동 저장을 제외한 모든 결과와 처리 파일은 이 프로젝트 안에 저장했다.
