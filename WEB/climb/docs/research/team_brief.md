# 맵 설계 팀 공통 지침

## 목표
"피유 등반"(차지 점프 수직 등반 게임)의 맵을 **지금보다 확실히 어렵게, 그러나 공정하게** 다시 만든다. 사용자의 말: "지금은 솔직히 난이도가 높지 않아. 좀 더 어렵게 해서 성취감이 있게 하고 싶어." "실수하거나 미끄러지면 밑으로 주욱 떨어지는 구조." "아예 못 깰 난이도는 아니게."

## 먼저 읽을 것
1. `docs/research/jumpking_maps.md` — 조사 결과. 난이도 요소, 낙하 설계, 공정함 점검표, 현재 맵 진단, 권고 10개. **이 문서의 권고를 따른다.**
2. `public/physics.js` — 점프 수치와 감정이 5명의 능력.
3. `public/level.js` — 맵 틀과 지형 함수 `rock(c0,c1,h0,h1)`, `up(c,h,n,{to,depth})`, `down(...)`, `nod(c0,c1,h)`.
4. `docs/MAP.md` — 구간 테마.
5. `tools/validate.mjs`, `tools/route.mjs` — 검증 도구.

## 맵 틀 (바꾸지 않는다)
- 가로 32칸(칸 0과 31은 벽), 1칸 = 40px, 화면 1개 = 높이 18칸. 캐릭터는 폭 60px, 높이 48px.
- 구간 1 = 높이 0~117 (화면 1~6), 파일 `public/zones/zone1.js`. 시작 위치는 칸 3, 높이 0.
- 구간 2 = 높이 117~225 (화면 7~12), 파일 `public/zones/zone2.js`. 시작 바닥은 높이 117, 칸 1~22.
- 경계 발판 두 개는 고정이다: `rock(1, 22, 115, 117)` (구간 1 맨 위, zone1.js 안), `rock(1, 14, 223, 225)` (구간 2 맨 위, zone2.js 안).
- 자기 구간 파일 **한 개만** 고친다. `level.js`, `physics.js`, `main.js`, 다른 구간 파일, 도구는 고치지 않는다. 새 장치(바람 등)를 만들지 않는다. 쓸 수 있는 것: 덩어리, 경사(닿으면 미끄러짐), 꾸벅 발판(2초 서면 꺼짐, 구간 2 전용), 벽 튕김, 낮은 천장.
- 각 파일의 `decor`(화살표 표지)도 새 경로에 맞게 고친다. 다음 발판이 화면에서 잘 안 보이는 곳에만 둔다.

## 반드시 지킬 조건
1. **5명 모두 혼자서 끝까지 갈 수 있다.** 검증기에서 5명 전부 "통과", "갇히는 곳 0".
2. 어떤 필수 점프도 차지 창이 6틱(0.05초) 아래로 내려가지 않는다.
3. 공정함: 착지점과 위험이 뛰기 전에 화면에 보인다. 떨어지는 곳이 정해져 있다. 갇히는 곳이 없다.
4. 특정 기존 게임의 화면 배치를 옮기지 않는다. 조사 문서의 **원리**로 새로 설계한다.
5. 테마는 그대로다. 구간 1 뉴욕 빌딩 숲(옥상, 비상계단, 물탱크, 간판, 차양 = 미끄러운 경사). 구간 2 크리스마스 마을(지붕, 굴뚝, 선물 상자, 눈 쌓인 경사, 꾸벅 발판 = 푹 꺼지는 눈더미). 화면마다 주석으로 화면 이름과 의도를 적는다.

## 난이도 목표 (조사 문서 권고에서)
| | 구간 1 | 구간 2 |
|---|---|---|
| 상한 있는 점프 비율(끝까지 눌러도 되는 점프가 아닌 것) | 50% 이상 | 75% 이상 |
| 보통 점프의 창 | 0.15~0.20초 | 0.10~0.15초 |
| 화면당 가장 좁은 창 | 0.10초 안팎 | 0.083초 안팎 |
| 관문(화면 6, 12)의 가장 좁은 창 | 0.058~0.067초 | 0.058~0.067초 |
| 화면당 점프 수 | 5~7번 | 5~7번 |
- 화면 3부터 화면마다 병목 점프 1개. 일반 실수는 0~8칸 낙하, 병목 실패는 18~36칸, 관문 실패는 54~90칸.
- 관문 직전 화면(5, 11)은 숨 고르기. 관문이 구간에서 가장 어렵다.
- 화면 1~2는 가르치는 곳이다. 낮은 낙하로 장치(천장 아래 톡 점프, 벽 튕김, 경사)를 먼저 겪게 한다.
- 낙하 경로를 설계한다. 경사와 통로를 이어 "주욱" 떨어지게 하고, 도착 지점은 넓은 받이 바닥으로 정한다.
- 같은 종류의 점프를 3번 잇지 않는다.

## 검증 방법
- 구간 1만: `TO=117 node tools/validate.mjs` / 구간 2만: `FROM=117 node tools/validate.mjs`
- 옵션: `--map`(맵을 글자로 출력), `--all`(5명 모두의 경로와 창), `--skips`(3칸 넘게 오르는 모든 점프 = 의도하지 않은 지름길 찾기).
- 검증기는 "가장 넓은 길"을 보고한다. 그래서 **쉬운 지름길이 하나라도 있으면 그 길이 보고된다.** `--skips`로 지름길을 찾아 막는다.
- `node tools/route.mjs <id> <fromH> <toH> <dir -1|1> [cMin] [cMax]` — 한 점프의 출발 칸과 차지 범위.
- 다른 구간 담당이 동시에 작업 중이다. 실행이 문법 오류로 실패하고 원인이 다른 구간 파일이면 30초 뒤 다시 실행한다.
- 검증기는 공중에서 방향키로 살짝 움직이는 기능(모두 가능, 약함)을 계산하지 않는다. 그 기능 없이도 깰 수 있어야 한다.

## 일하는 순서
1. 문서와 코드를 읽는다.
2. 6화면의 설계안을 먼저 글로 쓴다(화면별: 이름, 의도, 가르치는/시험하는 것, 병목 점프, 실패하면 어디로 떨어지는지).
3. 화면 하나씩 만들고 검증한다. 한 화면이 목표에 맞은 뒤 다음 화면으로 간다.
4. 끝나면 `--all`, `--skips`로 전체를 확인한다.

## 마지막 답에 적을 것
- 화면별 표: 화면 이름 / 점프 수 / 가장 좁은 창(초) / 상한 있는 점프 수 / 병목 실패 시 낙하 칸 수.
- 5명의 검증 결과 줄(그대로 붙인다).
- 목표에 못 맞춘 항목과 이유. 확인하지 못한 것.

## 변경 (2026-11-11, 사용자 요청)
- **전면 재구성.** 기존 지형을 손보지 않고 화면 전부를 새로 설계한다.
- **길이를 늘려도 된다.** 구간마다 7~9화면까지. 구간 파일에 `export const top = <꼭대기 높이>;`를 적고 맨 위 쉼터를 `rock(1, 22, top - 2, top)`(구간 1) / `rock(1, 14, top - 2, top)`(구간 2)로 둔다.
- 구간 2는 계속 "117에서 시작"하는 기준으로 높이를 쓴다. 구간 1이 길어지면 level.js가 구간 2를 통째로 위로 옮긴다.
- 검증 명령: `ZONE=1 node tools/validate.mjs`, `ZONE=2 node tools/validate.mjs`. (`TO=`, `FROM=`은 쓰지 않는다.)

## 구간 3~5 추가 지침 (2026-11-12)
- 구간 파일: `public/zones/zone3.js`(구름 위 성), `zone4.js`(열기구 축제 하늘), `zone5.js`(로켓 발사대와 우주). 지금은 임시 발판만 있다. 전부 새로 쓴다.
- **높이는 "내 시작 바닥이 0"이라고 보고 쓴다.** level.js가 실제 높이로 옮긴다. 검증기 출력의 높이는 "파일 높이 + 구간 시작 높이"(첫 줄 `구간 N: 높이 A~B`의 A)다.
- 시작 바닥은 아래 구간의 맨 위 쉼터(칸 1~14, 내 높이 0)다. 시작 위치는 칸 3. 맨 위 쉼터는 `rock(1, 14, top - 2, top)`으로 둔다. 쉼터 옆(칸 15~30)으로 걸어 나가 아래 구간으로 떨어지지 않게, 쉼터 높이 근처에서 받는 바닥을 둔다(구간 2의 구덩이 문제를 되풀이하지 않는다).
- 길이: 구간마다 6~8화면(top = 108~144 + 쉼터). 파일에 `export const top = <높이>;`.
- 형식: `export default function build({ rock, up, down, nod, hot, boost, wind }) { ... }`, `export const decor = [...]`.
- 검증: `ZONE=3 node tools/validate.mjs [--all --skips --map]` (4, 5도 같다). 구간 하나는 5~25초 걸린다.
- 구간 3은 1·2보다, 4는 3보다, 5는 4보다 어렵다. 하한은 어디서나 6틱(분노 포함). 분노는 창이 약 0.7배라서 좌절이 8~9틱이 사실상 바닥이다.
- 화면별 가장 좁은 창 목표(좌절이): 구간 3은 8~11틱, 구간 4는 8~10틱, 구간 5는 8~9틱. 상한 있는 점프 비율 70% 이상. 화면당 점프 5~7번. 같은 병목을 3번 되풀이하지 않는다(구간 2의 굴뚝 튕김 3연속이 지적받았다).
- 낙하: 병목 실패 18~40칸, 관문 실패 60~100칸(구간 안에서 끝난다. 아래 구간으로는 떨어지지 않는다). 낙하 도착 지점은 닫힌 받이 바닥. 떨어진 뒤 돌아오는 길이 본 길보다 어렵지 않게.

### 장치 (physics.js, level.js에 이미 구현됨. 고치지 않는다)
| 함수 | 뜻 | 쓰는 구간 |
|---|---|---|
| `rock`, `up`, `down` | 덩어리, 경사(닿으면 미끄러져 끝에서 날아감) | 전부 |
| 낮은 천장 | 덩어리를 머리 위에 둔다. 머리를 박으면 위로 가던 힘이 사라진다 | 구간 3의 주제 |
| `nod(c0, c1, h)` | 꾸벅 발판: 2초 서면 꺼지고 3초 뒤 돌아온다 | 구간 2의 것. 3~5에서 섞어 써도 된다 |
| `wind(c0, c1, h0, h1, ax)` | 바람 구역: 그 안의 **공중에서만** 가로로 민다. ax = 가속 px/s² (+는 오른쪽). 항상 분다(꺼지지 않는다). 점프의 가로 속도는 400px/s 고정이라 ax 300이면 1초에 속도가 300 바뀐다. 권장 100~400 | 구간 4의 주제. 5에서 섞어도 된다 |
| `hot(c0, c1, h)` | 달궈진 판: 1.8초 서 있으면 위로 튕겨 낸다(모으던 힘은 사라지고 거의 제자리로 떨어진다). 판은 사라지지 않는다. 검증기는 보통 바닥으로 계산한다. 걷는 시간 + 차지 시간 + 반응 0.25초가 1.8초 안이어야 한다(걷기는 초당 4.5칸, 최대 차지 0.8초, 분노 0.6초) | 구간 5 |
| `boost(c0, c1, h)` | 분사 판: 여기서 뛰면 점프 속도가 1.4배(높이 약 2배, 최대 약 15.7칸). 검증기가 계산한다 | 구간 5 |
- 새 장치는 구간 첫 화면에서 낮은 낙하(6칸 이하)로 먼저 가르친다. 바람은 "같은 점프가 바람 안팎에서 다른 곳에 닿는다"를 안전하게 보여 준다.
- 바람 구역은 화면에 깃발과 바람 줄무늬로 보인다. 구역 경계를 발판·벽에 맞춰 눈으로 알 수 있게 한다.

## 변경 (2026-11-12): 고유 능력 끔
- 감정이 5명이 모두 같은 기본 물리다. 검증기는 한 명(defeated)만 계산해 한 줄만 낸다. "5명 통과"는 "defeated 통과"로 읽는다.
- 분노의 0.7배 창, 지침이의 느린 낙하, 짜증이의 강한 튕김을 고려하지 않는다. 하한 6틱과 화면별 창 목표는 그대로다.
