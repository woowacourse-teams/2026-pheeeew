# 구간 1·2 새 맵 심사 보고서 (난이도·공정함)

작성일: 2026-11-11. 대상: `public/zones/zone1.js`, `public/zones/zone2.js`. 파일은 고치지 않았습니다.

## 1. 판정

**수정 필요.** 5명 모두 통과하고 갇히는 곳은 없습니다. 그러나 (가) 구간 2 시작 쉼터에서 구간 1 관문으로 도로 떨어지는 구멍이 있고, (나) 벽난로가 닫힌 받이가 아니며, (다) 경사 중간에 서 버리는 물리 결함이 있고, (라) 구간 2가 구간 1보다 쉽습니다.

## 2. 측정 방법

- 검증기: `node tools/validate.mjs --all --skips --map`, `ZONE=1`, `ZONE=2`. 결과는 5명 모두 "통과, 갇히는 곳 0". 가장 좁은 창은 구간 1이 8/9/8/8/6, 구간 2가 11/12/11/11/8입니다(좌절이/지침이/답답이/짜증이/분노).
- 낙하 측정: 검증기와 같은 방식으로 모든 자리·방향·차지를 `physics.js`의 `step`으로 돌리고 착지 높이를 전부 보관했습니다. 각 점프에서 창이 가장 넓은 자리를 골라, 창 바로 아래 1~6틱(부족)과 바로 위 1~6틱(과함)의 착지 높이를 읽었습니다.
- 수정안 시험: 파일을 고치지 않고 `level.tile`을 덮어써서 칸만 바꾼 뒤 같은 분석을 돌렸습니다. "측정"이라고 적은 수정안은 이 방법으로 확인한 것입니다.
- 스크립트 위치: `<scratch>/` (`lib.mjs`, `paths.mjs`, `odd.mjs`, `q3.mjs`~`q7.mjs`).
- 창 단위는 틱(1/120초)입니다. 8틱 = 0.067초, 12틱 = 0.100초, 18틱 = 0.150초.
- 본 길은 "병목을 기준으로 앞뒤를 다시 푼 가장 넓은 길"입니다. 검증기는 병목 뒤쪽에서 좁은 지름길을 아무거나 골라 보고하기 때문입니다(전체 실행에서 172→179 창 8이 나오는 이유).

**A. 구간 2 시작 쉼터 오른쪽 구덩이 (화면 7, 높이 117, 칸 23~30)** [측정]

- 빠져나올 수는 있습니다. 114에서는 점프 1번(창 48)입니다. 98, 90, 86에서는 점프 6~9번이고 **구간 1 관문 병목(창 8, 분노 6)을 다시 지나야 합니다.**
- 수정안 [측정, 5명 통과, 가장 좁은 창 변화 없음]: `zone1.js`
  - `rock(23, 23, 109, 110);` → `rock(23, 24, 109, 110);`
  - `rock(29, 30, 112, 114);` → `rock(25, 30, 110, 114);`
  - 결과: 시작 바닥에서 떨어지는 모든 경우가 114에 섭니다(3칸). 걸어 떨어져도 114입니다. 110→114는 창 36, 114→117은 창 51이 됩니다.

**B. 벽난로가 닫힌 받이가 아님 (높이 149, 칸 25~30)** [측정]
- 1층 바닥(151~153) 밑 149~151이 왼쪽으로 뚫려 있습니다.
- 재현: 벽난로에서 왼쪽으로 걸으면 높이 117까지 32칸 더 떨어집니다. 벽난로의 모든 자리에서 왼쪽으로 뛰면 2880번 중 1057번이 높이 135(매달린 선물 상자)에 떨어집니다. 문(153)에 서는 것은 311번입니다. 창이 가장 넓은 자리(칸 27.8, 창 31)에서는 부족해도 제자리입니다.
- 관문에서 68칸 떨어진 사람이 한 번 더 14~32칸 떨어집니다. 설계 메모의 "벽난로까지"와 다릅니다.
- 수정안 [측정]: `zone2.js`의 `rock(15, 24, 151, 153);` 다음 줄에 `rock(22, 24, 149, 151);`을 넣습니다. 결과: 벽난로에서 뛰면 153 아니면 149에만 섭니다. 왼쪽으로 걸어도 149입니다. 구간 2 창은 그대로입니다.

**C. 경사 중간에 서 버림 (물리 결함)** [측정, 원인도 확인]
- 경사에 닿으면 미끄러져야 하는데, 경사 칸의 아래쪽 모서리 근처로 떨어지면 그 자리에 섭니다. 좌절이 기준 881건, 서로 다른 자리 90곳입니다.
- 위치: 화면 2 차양(높이 19, 20, 21), 관문 유리 지붕(높이 91~97), 구간 2 지붕(높이 208~213).
- 본 길에서 나오는 경우: 102→104를 1틱 또는 5틱 넘치면 유리 지붕 높이 96에 섭니다(나머지는 63칸 낙하). 213→217을 3~5틱 넘치면(분노) 지붕 높이 208에 섭니다(나머지는 60~64칸 낙하). 208에서는 188까지만 내려가는 점프가 있어서, 1틱 차이로 64칸 낙하와 25칸 낙하가 갈립니다.
- 갇히지는 않습니다. 유리 지붕에서는 어느 쪽으로 뛰어도 높이 39로 갑니다.
- 원인: `physics.js` 212~223행이 꽉 찬 칸을 경사보다 먼저 봅니다. 경사 칸 밑을 채운 칸(`to`, `depth`)의 윗면에 먼저 걸립니다.

  ```js
  if (p.vy > 0 && slopeDepth(level, p.x, ny, P) > 0) { p.y = ny; beginSlide(p, slopeUnder(level, p.x, ny, P), P); return; }
  ```
  결과: 목록 밖 착지 881 → 0 (5명 모두 0). 5명 통과. 가장 좁은 창은 지침이의 구간 2만 12 → 11로 바뀌고 나머지는 같습니다.

## 6. 확인하지 못한 것

- 사람이 직접 하지 않았습니다. 창과 낙하는 모두 계산값입니다.
- 공중 허우적(방향키)은 계산하지 않았습니다. 답답이의 센 허우적으로 생기는 지름길이나 탈출은 모릅니다.
- 낙하 값은 "창이 가장 넓은 자리"에서 차지만 틀린 경우입니다. 다른 자리에서 뛴 경우는 3장의 "가장 나쁜 낙하"와 벽난로 분포로만 봤습니다.
- 꾸벅 발판은 "전부 켜짐"과 "전부 꺼짐" 두 상태만 계산했습니다. 눈더미 시간은 착지 뒤 바로 걷는다고 가정했고 사람의 반응 시간은 넣지 않았습니다.
- 수정안 시험은 3명 또는 5명으로 했습니다(항목마다 적었습니다). 여러 수정안을 함께 넣었을 때의 `--skips` 지름길은 확인하지 않았습니다.
- 화살표 표지(`decor`)의 위치, 그림과 충돌 상자의 어긋남, 떨어지는 동안 카메라가 따라가는 속도는 보지 않았습니다.
- 5.1의 3, 4와 5.2의 3 추가 안, 4, 5는 시험하지 않은 추정입니다.
