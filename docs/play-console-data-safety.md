# Google Play 데이터 보안 답변 초안

이 초안은 2026-09-16 현재 저장소의 구현을 기준으로 합니다. Play Console 제출 직전에 실제 릴리스 AAB 와 서버 동작을 다시 확인해야 합니다.

> **2026-09-16 갱신.** 이전 초안은 "운영자 서버로 기기 위치 전송: 없음", "기기 위치 영구 저장: 없음" 을 전제했습니다. **서버 기능이 연결되면서 두 전제가 모두 깨졌습니다.** 아래는 현재 구현 기준으로 다시 작성한 것입니다.

## 현재 구현 기준

### 앱이 기기 밖으로 보내는 것

| 항목 | 저장 여부 | 설명 |
| --- | --- | --- |
| **흐리게 처리한 위치** | **영구 저장** | 실제 좌표가 아님. 앱이 반경 300m 원 안에서 무작위로 옮기고, 서버가 다시 반경 300m 원 안에서 무작위로 옮긴 값만 저장 |
| **한숨 메모** | **영구 저장** | 사용자가 입력한 최대 50자 텍스트 |
| **서버가 만든 기기 식별자** | **영구 저장** | 무작위 UUID. OS 가 주는 식별자(광고 ID, IMEI, MAC)가 아님 |
| 좋아요, 신고, 차단 기록 | **영구 저장** | 대상 한숨과 기기 식별자 |
| 무결성 증명 | **저장 안 함** | 검증에만 사용. Android 는 검증을 위해 Google 로 전달 |
| 서버 접속 기록 | Grafana Cloud 보관 정책 | IP, 경로, 응답 코드. 오류이거나 1초 초과 요청만 |

### 앱이 보내지 않는 것

- **실제 GPS 좌표** — 기기 안에서만 처리하고 흐리게 만드는 계산의 입력으로만 사용
- **마이크 녹음 내용** — 숨의 세기만 기기 안에서 측정
- 이름, 이메일, 전화번호, 계정, 결제 정보
- 광고 ID, IMEI, MAC 주소 등 OS 기기 식별자
- 앱 사용 분석, 크래시 수집, 푸시

### 권한

`ACCESS_COARSE_LOCATION`, `ACCESS_FINE_LOCATION`, `RECORD_AUDIO`, `INTERNET`, `ACCESS_NETWORK_STATE`

## 제안하는 답변

**확정이 아닙니다.** Play Console 의 당시 정의를 보고 최종 결정해야 합니다.

| 데이터 유형 | 수집 | 공유 | 목적 | 필수 | 근거 |
| --- | --- | --- | --- | --- | --- |
| 위치 → **대략적인 위치** | 예 | 아니오 | 앱 기능 | 선택 | 흐리게 처리했지만 **영구 저장**하므로 "수집" 이고 "일시적" 이 아님 |
| 위치 → 정확한 위치 | **아니오** | — | — | — | 실제 좌표는 기기 밖으로 나가지 않음 |
| 앱 활동 → **기타 사용자 제작 콘텐츠** | 예 | 아니오 | 앱 기능 | 선택 | 한숨 메모 |
| 앱 정보 및 성능 → 기타 앱 성능 데이터 | 예 | 예 | 분석 | 필수 | 서버 오류 로그. Grafana Cloud 로 전송 |
| 기기 또는 기타 ID | **판단 필요** | 아니오 | 앱 기능 | 필수 | 아래 참고 |
| 오디오 → 음성 또는 사운드 녹음 | **아니오** | — | — | — | 세기만 기기 안에서 측정하고 녹음을 저장·전송하지 않음 |

### 기기 또는 기타 ID — 판단이 필요합니다

서버가 만든 무작위 UUID 를 저장합니다. **OS 가 제공하는 기기 식별자가 아니라 설치 단위로 서버가 부여한 값**입니다.

- **수집 안 함으로 보는 해석** — Google 의 "기기 또는 기타 ID" 정의가 기기에서 읽어 오는 식별자를 가리킨다고 보는 경우
- **수집으로 보는 해석** — 설치 단위로 지속되며 여러 요청을 연결할 수 있으므로 보수적으로 신고

**보수적 해석을 권합니다.** 잘못된 "수집 안 함" 은 정책 위반이 될 수 있고, "수집" 으로 신고해서 생기는 불이익은 없습니다.

### 반드시 함께 답해야 하는 것

| 질문 | 답 | 근거 |
| --- | --- | --- |
| 전송 중 암호화 | **예** | 앱과 서버, 외부 서비스 모두 HTTPS |
| 사용자가 데이터 삭제를 요청할 수 있는가 | **예** | 개인정보처리방침 제8조. 이메일로 요청 |
| 데이터 수집이 필수인가 | 일부만 | 한숨 남기기는 선택, 서버 로그는 필수 |

**"데이터 삭제 요청" 답이 이전과 달라집니다.** 예전에는 저장하는 데이터가 없어 삭제 절차가 필요 없었지만, 이제는 있습니다. Play Console 에 **삭제 요청 URL 또는 안내 경로**를 제출해야 할 수 있습니다.

## 제출 전 확인할 것

- [ ] 릴리스 AAB 의 권한 목록이 위와 같은지
- [ ] Play Console 의 "기기 또는 기타 ID" 정의가 서버 발급 식별자를 포함하는지
- [ ] 데이터 삭제 요청 경로를 제출 양식에 어떻게 넣을지
- [ ] 개인정보처리방침 URL 이 최신본을 가리키는지
- [ ] App Store 의 App Privacy 답변도 같은 기준으로 갱신했는지

## App Store 도 갱신이 필요합니다

App Store Connect 의 App Privacy 는 Play 와 항목 체계가 다릅니다. 최소한 아래를 다시 봐야 합니다.

- **Location → Coarse Location**: 수집함, 앱 기능, **사용자에게 연결됨(Linked)** 여부 판단 필요
- **User Content**: 한숨 메모
- **Identifiers**: 서버 발급 식별자를 Device ID 로 볼지 판단 필요
- **Diagnostics**: 서버 오류 로그

iOS 는 App Attest 증명을 **기기가 Apple 에 직접 요청**하므로 운영자가 Apple 로 보내는 데이터는 없습니다.
