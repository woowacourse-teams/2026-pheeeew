# 핀 응답·렌더링 실기기 측정 — 2026-10-11

- 기기: SM-S711N / Android 15
- 조건별 반복: 30회, 준비 실행 제외
- 빌드: 현재 저장소의 공유 렌더러를 쓰는 별도 release APK, 난독화 없음
- 지도 확대: 14, 카메라 고정, 기기 USB 연결 및 충전
- 고정 데이터는 기본 감정 아이콘 5종. 실서버 데이터는 응답의 원래 핀 모양 사용
- 지도와 native texture 캐시를 준비한 후 측정
- 개발 API에는 별도 측정 앱의 dev 기기 세션으로 접속
- 고정 데이터 서버: Mac의 127.0.0.1:8765, adb reverse를 거친 HTTP, 페이지당 최대 200개
- 프레임 완료 콜백에서 렌더 버전과 실제 rendered feature ID를 확인

①은 페이지별 HTTP 요청 시작→본문 전체 수신, ②는 각 페이지 본문 수신→해당 페이지까지의 화면 대상 핀 표시, ③은 첫 HTTP 요청→마지막 페이지 전체 표시이다.
②는 JSON 해석·도메인 변환·누적 정렬·Compose 갱신·이미지 준비·native source 갱신·프레임 대기를 포함한다.
페이지 갱신이 합쳐지면 앞선 페이지의 ②는 그 핀을 포함한 후속 프레임까지의 시간이다. 순수 GPU 처리 시간으로 해석하지 않는다.

## 검증 및 해석의 한계

- 응답 수·화면 대상 수·페이지 수와 구간 시간 합계 검증 통과
- 측정 결과: {'success': 300}
- P95는 조건별 30회에서 계산한 탐색적 값이다. 재현성과 기기 간 비교에는 더 많은 반복이 필요하다.
- 프레임별 feature 조회 및 파일 기록이 포함된 계측 결과다. 순수 렌더 시간이나 사용자 배포 빌드의 절대 성능과 동일하지 않다.
- 핀은 겹침을 허용한다. 화면 feature ID 개수는 픽셀에서 개별 핀이 육안으로 구별되는 개수와 다르다.
- 고정 데이터는 기본 감정 이미지 5종이다. 다양한 그룹 스탬프, 캐시 없는 첫 실행, 이동 중 지도는 별도 조건이다.
- 현재 연결을 열 수 있는 Android 기기만 측정했다. iPhone은 실제 CoreDevice 연결을 열 수 없었다.
- 설치된 사용자 앱 2.2.1 대신 현재 소스의 별도 측정 앱을 사용했다.
