## 1. 공통 조건

- 기기: Samsung SM-G977N · Android 12 · 약 60Hz · USB 전원 · Wi-Fi
- 앱: Debug 2.6.0(14) · 개발 서버 · HTTP 입력 + WS 수신
- 기존 앱은 보존하고 별도 실험 패키지를 설치했다. 푸시 토큰 등록은 비활성이다.

- 회차 사이 최소 60초 대기. 목표 간격과 실제 입력 발행 간격을 따로 기록한다.

## 4. 판정 범위

- 입력 반응은 앱 콜백부터 Compose 그리기 코드까지다. 실제 패널 표시 시각은 측정하지 않는다.
- 프레임 시간은 완료 시각이 있는 표본으로 계산한다. 마감 초과는 전체 수집 프레임의 FrameTimeline 판정을 사용한다.
- 완료 시각이 유효하지 않거나 추적 종료에 걸린 프레임은 시간 표본에서 빠진 개수를 공개한다.
- 기기 간 입력→화면 종단 지연은 미측정이다. 서로 다른 기기의 시각을 직접 빼지 않는다.
- 아직 후보 방식과 비교하지 않았으므로 수신 방식의 우열을 판정하지 않는다.

## 6. 제외한 실행

- 첫 시도: 프레스 화면 미진입. 앱 수락 0회로 예열 검증 실패, 측정 500회 미실행.
- 두 번째 시도: 예열 50회 적용 후 프레임 추적 설정 오류. 측정 500회 미실행.
- 20회 예비 입력: 도구 확인용으로 별도 보존하며 본 측정에 합산하지 않는다.

## 8. Android 실기기 후속 시나리오

- 측정 대상 A: Samsung SM-G977N 실기기 · Android 12.
- 입력 보조 B: iOS 26.5 시뮬레이터 · dev 앱 2.6.0 (14) · HTTP POST. iOS 실기기 성능 측정은 하지 않았다.
- 아래 여섯 시나리오는 각각 3회차를 완료했다. Android Perfetto 추적은 18/18회 수집했다.
- 점수 반영을 확인했다. 순위·활동 인원 변화는 이 실행에서 따로 검증하지 않았다.

- 서로 다른 기기의 시각은 빼지 않았다. 기기 간 입력→화면 종단 지연과 실제 패널 표시 완료 시각은 미측정이다.

### 실행기 오류와 재측정

- 보조 실행기 결과가 여러 줄 JSON일 때 파싱하지 못하던 문제를 수정했다. 이후 B 입력 적용 건수를 파싱해 Android 점수와 대조했다.
- 단일 입력·화면 복귀 실행이 점수를 한 번 확인한 뒤 같은 변화를 다시 기다려 부분 실패로 기록되던 검증 로직을 수정했다. 재실행한 3회차는 모두 완료됐다.
- 네트워크 3회차는 앱의 `Unavailable` 로그가 없으면 입력 전에 중단되던 실행기 조건을 수정했다. 실제 Wi‑Fi·모바일 데이터 상태를 단절 확인에 사용하고, 앱 경로 로그는 관측값으로 기록했다. 수정 후 10/10사이클을 완료했다.
- 동시 입력 첫 2회차 시도에서는 B 입력 100회 중 97회만 적용됐다. 재측정은 100/100회 적용됐고 점수도 맞았다. 최초 3회 누락 원인은 로그만으로 확인되지 않았다.

### 원본 자료

시나리오별 JSON 원본도 로컬에 보관했으며 PR에는 포함하지 않았다. 기본 입력·동시 입력·개별 입력은 `/private/tmp/1114-physical-20261106/scenario-helper/runs/parser-verified/` 및 `parser-retry-*` 아래에 있다. 재진입·백그라운드·네트워크 단절 자료는 각각 `parser-retry-tab-reentry/`, `parser-retry-background-return/`, `parser-retry-network-outage-v2/`, `parser-retry-network-outage-v3/` 폴더에 있다.

## 9. 이후 수신 방식 비교 범위

- WS·캐시 폴링·SSE·기본 폴링은 같은 Android 실기기와 동일한 입력·화면 조건에서 비교한다. iOS 성능 측정은 범위에서 제외한다. iOS 시뮬레이터는 필요한 경우 다른 사용자 입력을 발생시키는 보조 기기로만 쓴다.
- 이번 WS 기준에서 실제 측정한 입력 적용·화면 그리기·프레임·재진입·백그라운드·네트워크 복구 지표만 후보 비교에 사용한다.
- 기기 간 종단 지연, 실제 패널의 빛 표시 시각, 순위·활동 인원 변화는 비교 지표에서 제외한다. 소켓 손실이 관측되지 않은 8회는 복구 시간 비교에서 제외한다.
- 성능·복구 목표값은 합의되지 않았으므로 수신 방식 우열 판정에 임의의 합격선을 적용하지 않는다.
