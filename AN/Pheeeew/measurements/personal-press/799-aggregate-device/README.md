# #799 집계 조회 합치기 실기기 비교

2026-10-18 USB Galaxy S10 5G(SM-G977N), Android12/API31, Wi-Fi, USB 충전, Debug 측정 전용 com.pheeeew.pressprobe와 실제 api-dev 서버. 두 빌드 모두 입력 묶음500ms, 감정별30/전체100, POST 후 첫 입력의 남은 대기 적용 상태다. before는 집계 합치기 없음, after는 1초 간격으로 집계 조회를 합치고 전송 워커와 분리한 후보다. 기준은 이번 새로 실행한 before이며 이전 다른 측정과 수치를 합치지 않는다.

## 구현

성공 전송 후 버퍼가 비면 전체 집계 조회를 한 개 Job으로 예약한다. 예약 중 추가 성공은 dirty 상태로 합치고 첫 예약을 뒤로 미루지 않는다. 조회 후 새 성공이 있거나 응답이 오래됐으면 다음 간격에 다시 조회한다. 일반 집계 GET이 다음 POST를 막지 않는다. 조회 시작 세대보다 새 POST 성공/개인·전체 조회가 진행됐거나, 반환 시 POST가 진행 중/처리 불명이면 그 집계를 적용하지 않는다. 오래된 응답으로 optimistic coverage를 중복 차감하지 않게 한다. 처리 불명 복구의 별도 조회·재시도 경로는 유지한다.

집계 조회 주기는 내 입력의 로컬 반응 및 POST 확인과 별개다. 다른 사용자의 최신 집계가 보이는 주기는 이전보다 느려질 수 있다. 1초는 예약 간격이며 네트워크 지연·오래된 응답 폐기까지 포함한 절대 최신성 보장은 아니다.

## 조건과 결과

실제 PressScreen을 표시하고 ViewModel에 자동 입력했다. 단발1회, 5회 연타(100ms 간격), 같은 감정100회 및 교차100회(100ms 간격)를 각3회씩 실행했다. 순서는 before1 → after1 → after2 → before2 → before3 → after3. 전후 모두 상태가 1.3초 연속 안정될 때까지 기다려 마지막 예약 집계 요청을 포함하고, 별도 개인/전체 GET으로 서버 증가량을 검증했다. 이 대기 절차가 이전 post-wait 측정과 다르므로 과거 수치와 직접 합산하지 않는다.

| 연속 입력600회씩 | before | after |
|---|---:|---:|
| POST | 104 | 102 |
| 전체 집계 GET | 72 | 57 |
| 개인 집계 GET | 6 | 6 |
| HTTP 합계 | 182 | 165 |
| 회차별 확인p95 범위 | 577~600ms | 572~577ms |
| 최대 대기 입력 | 8 | 8 |

총요청9.3% 감소, 전체 집계 GET20.8% 감소. HTTP 합계는 각조건 마지막 검증용 개인GET1/전체GET1을 포함한다. 연속입력6조건의 고정 검증 요청12개를 빼면170→153회(10% 감소)다. 초기화 조회는 run_start 이전이므로 포함하지 않는다. 확인 지연은 입력 계측 로그→Accepted 결과 처리 로그, 화면 그리기 시간이 아니다.

단발은 전557~624ms / 후609~703ms로, 개선 후1회703ms가 있었다. 짧은 연타p95는 전572~587ms / 후571~577ms. 단발·짧은 연타는 각조건POST1회 및 총HTTP4회로 동일했다. 연속입력 확인 지연의 악화는 관찰하지 않았지만 모든 UX가 동일함을 증명한 결과는 아니다. 물리 터치·애니메이션 프레임은 미측정이다.

전체24조건 입력1236회, 확인표본1236개, 서버 증가1236회. 각감정 증가량도 앱에서 검증했고 각조건pending0을 확인했다. 이번 전경 실행 조건의 누락은0이다. 앱 종료·백그라운드·오프라인·장애 주입 조건에서의 유실 방지나 중복 방지 보장은 이 결과에 포함하지 않는다. 단일기기Debug 측정으로 다중 사용자 서버 수용량을 추정하지 않는다. 응답 지연은 고정하지 않은 실제 개발 서버 결과이며 반복3회는 제한된 표본이다.
