# #799 POST 중 유입 입력의 묶음 대기 보완

2026-10-18, an/dev 0f725625 기반 로컬 미커밋 변경. 첫 입력 시각 + 500ms를 조회 종료뿐 아니라 POST 후 다음 묶음에도 사용한다. 요청 간격 100ms 이후 남은 묶음 대기만 적용한다. 감정별 30/전체 100 기준은 유지한다.

POST 100/500/1000/3000ms 도중 새 입력을 수용하는 경계 회귀 테스트를 추가했다. 첫 입력 시각 기준 대기가 만료됐으면 추가 500ms를 부과하지 않는다. 서버 반영 수와 직렬 전송도 검사한다.

## 같은 조건 비교

가상 시간의 같은 감정 100회, 100ms 간격. 초기 조회 제외 전체 GET 수를 기록한다. 실기기 결과가 아니다.

| POST/GET 지연 | POST 전→후 | 전체 GET 전→후 | 확인 p95 전→후 |
|---|---:|---:|---:|
| 40/50ms | 17→20 | 9→1 | 680→540ms |
| 500/50ms | 10→17 | 1→1 | 1600→1100ms |
| 1000/50ms | 7→10 | 1→1 | 2600→2100ms |

빠른 응답 조건의 POST+전체 GET은 26→21회이나, 느린 POST에서는 POST 증가가 총요청 증가로 이어진다. 불필요한 대기를 제거했으므로 요청 수 감소를 일반화할 수 없다. 이전 CSV와 iPhone 로그는 과거 구현의 결과로 그대로 보존하며 이번 변경의 실기기 결과로 사용하지 않는다.

짧은 연타 5회(50ms 간격)+750ms 휴식, 10회 반복 시 현재 제품 후보는 GET 3초에서 p95 2610ms다. 조회 분리·합치기 후속 후보는 별도 재현 폴더에 보존했다. 해당 후보는 기존 회귀 테스트 5개와 충돌하므로 #799 제품 코드에 포함하지 않았다.

원본 JUnit 출력: 799-post-wait-before.xml / 799-post-wait-after.xml. 수치: 799-post-wait-comparison.csv. before는 이번 보완 이전 #799 코드이고, 최초 an/dev 원본과는 다르다.

## 최종 검증

`ANDROID_HOME=/Users/USER/Library/Android/sdk ./gradlew :shared:testAndroidHostTest --tests '*Press*Test' --tests '*Tap*Test' ktlintCheck :androidApp:assembleDebug` 성공. 62개 테스트, 실패·오류·건너뜀 0. Android Debug 빌드 성공. 실기기 실행과 프레임 측정은 이번 실행에 포함하지 않았다.

## USB 실제 기기 비교

[Galaxy S10 5G 전후 3회 결과](799-post-wait-device/README.md): 연속600회 POST89→104, POST+GET131→198. 확인 지연은 줄었으나 요청 비용이 증가하여 이 변경만으로 요청 최소화 목표를 만족하지 못한다. 원본 로그·분석 스크립트·CSV·실제 화면을 함께 보존했다.

## 집계 조회 합치기 구현 및 실기기 검증

[집계 조회 합치기 실기기 결과](799-aggregate-device/README.md): 동일한 POST 대기 개선을 적용한 전후 각3회 비교에서 연속600회 총요청182→165(9.3% 감소), 확인p95 회차범위577~600→572~577ms. 전체입력1236회와 서버 증가량 일치. 최신 구현은 집계 합치기와 오래된 응답 방어까지 포함하며, 앞선 post-wait 결과는 과거 단계의 기록이다.
