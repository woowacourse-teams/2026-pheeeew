# #799 POST 중 유입 입력의 묶음 대기 보완

2026-10-18, an/dev 0f725625 기반 로컬 미커밋 변경. 첫 입력 시각 + 500ms를 조회 종료뿐 아니라 POST 후 다음 묶음에도 사용한다. 요청 간격 100ms 이후 남은 묶음 대기만 적용한다. 감정별 30/전체 100 기준은 유지한다.

POST 100/500/1000/3000ms 도중 새 입력을 수용하는 경계 회귀 테스트를 추가했다. 첫 입력 시각 기준 대기가 만료됐으면 추가 500ms를 부과하지 않는다. 서버 반영 수와 직렬 전송도 검사한다.

## 같은 조건 비교

가상 시간의 같은 감정 100회, 100ms 간격. 초기 조회 제외 전체 GET 수를 기록한다. 실기기 결과가 아니다.

| POST/GET 지연 | POST 전→후 | 전체 GET 전→후 | 확인 p95 전→후 |
|---|---:|---:|---:|
| 40/50ms | 17→20 | 9→1 | 680→540ms |
| 500/50ms | 10→17 | 1→1 | 1600→1100ms |
| 1000/50ms | 7→10 | 1→1 | 2600→2100ms |

빠른 응답 조건의 POST+전체 GET은 26→21회이나, 느린 POST에서는 POST 증가가 총요청 증가로 이어진다. 불필요한 대기를 제거했으므로 요청 수 감소를 일반화할 수 없다. 이전 CSV와 iPhone 로그는 과거 구현의 결과로 그대로 보존하며 이번 변경의 실기기 결과로 사용하지 않는다.

POST 후 대기만 보완하던 당시 단계에서 짧은 연타 5회(50ms 간격)+750ms 휴식, 10회 반복은 GET 3초에서 p95 2610ms였다. 당시 조회 분리·합치기 후보는 회귀 테스트 5개와 충돌해 제품 코드에서 제외하고 별도 재현 폴더에 보존했다. 이후 아래 집계 합치기 단계에서 제품에 반영했으므로 이 제외 판단은 현재 구현을 뜻하지 않는다.

원본 JUnit 출력: 799-post-wait-before.xml / 799-post-wait-after.xml. 수치: 799-post-wait-comparison.csv. before는 이번 보완 이전 #799 코드이고, 최초 an/dev 원본과는 다르다.

## 집계 합치기 단계에서 회귀 테스트 5개를 조정한 근거

`df40c753`의 테스트 변경은 다음과 같다. 실패 조건을 제거한 것이 아니라, 전송과 집계 조회가 분리된 뒤의 기대 시점과 결과를 명시했다.

- `PressBatchWaitTest`의 느린 집계 조회: 두 번째 전송을 GET 완료 후 1600ms가 아니라 첫 입력 마감 1150ms로 검증하도록 변경했다. 이 테스트는 이번 리뷰에서 실제 GET 진행 중 입력하도록 다시 보강했다.
- `PressRepositoryLongQueueTest`의 처리 불명 복구와 날짜 변경: 두 테스트에서 100ms 대기를 1100ms로 변경해 1초 집계 예약 후 후속 전송까지 진행시켰다. 요청 ID 변경과 전송 수·서버 반영 검증은 유지했다.
- `PressViewModelTest`의 입력 확인: 1초 예약을 진행한 뒤 프레스 수·대기 수를 검증하도록 변경했다.
- `PressViewModelTest`의 오래된 전체 집계 응답: 1초를 진행해 gate로 막힌 전체 GET이 시작된 뒤 추가 입력을 주고 낙관적 전체 숫자를 검증하도록 변경했다.

집계 합치기의 상세 조건과 당시 실행 결과는 [실기기 비교 기록](../aggregate-device/README.md)을 참고한다. 위 커밋의 테스트는 당시 결과이며, 최신 패키지 이동 반영 후 검증은 별도로 수행한다.
