# 실시간 프레스 연결·입력 복구 연동

관련 이슈: [#923](https://github.com/woowacourse-teams/2026-pheeeew/issues/923),
[AN #888](https://github.com/woowacourse-teams/2026-pheeeew/issues/888).
기준은 [승인 계약 v2](../decisions/realtime-press-contract.md)와
[ADR-0041](../adr/0041-use-stable-ties-and-device-parallel-press-storage.md)입니다.
이 문서는 BE의 관찰 가능한 동작과 앱에서 확인할 항목을 구분합니다. 실제 AN 검증 완료 기록은 아닙니다.

## 연결과 인증

`/api/v1/press-race`의 HTTP Upgrade에 기존 `Authorization: Bearer <access token>`을 전달합니다.
기존 30분 JWT를 사용하고 쿼리 토큰이나 소켓 내 토큰 교체는 지원하지 않습니다.
프레스·전체 순위 화면에서 연결 하나를 공유하고 `view.change`로 화면을 전환합니다.
다른 탭·백그라운드에서는 앱이 연결을 종료합니다.

새 연결은 이전 연결의 진행 중 저장이 끝나기를 기다리고 DB에서 연결 세대를 교체합니다.
`session.init`으로 현재 화면과 미확인 입력을 보내 `session.ready`를 받은 뒤 새 입력을 재개합니다.
정산 결과와 확정 횟수·날짜는 같은 DB 관찰 상태입니다. 최초 스냅샷은 ready 송신 뒤 새 기준으로 전달합니다.
이전 연결의 지연 입력은 DB 저장 경계에서 차단하며, 이전 최종 결과는 변경하지 않습니다.

토큰이 만료되면 초기화·입력·화면 변경이 없는 연결도 `1008 / AUTH_EXPIRED`로 종료합니다.
앱은 기존 HTTP 토큰 재발급을 한 번에 하나만 수행한 뒤 새 연결로 복구합니다.
접속 실패·만료·전송 불능을 알면 새 입력을 중단하고 마지막 순위와 재연결 표시를 유지합니다.
활동 인원은 0으로 바꾸지 않고 알 수 없음으로 표시합니다. 공유 소켓이 끊기면 입력도 불가능합니다.

## 입력의 재시도와 정산

| 최초 전송 이후 | 앱 동작 |
| --- | --- |
| 10초 미만 | 같은 입력 ID·내용으로만 재시도. 입력별 지수 backoff는 250ms에서 최대 2초를 시작값으로 사용 |
| 10초 이상, 20초 미만 | `press.status`로 결과만 조회. ID를 묶어 초당 최대 1회 조회 |
| 20초 이상 | 자동 시도 중단·오류 표시·재연결 정산. 성공/실패를 임의로 확정하거나 새 ID로 가산하지 않음 |

앱은 미확인 입력을 최대 20묶음·직렬화 총 64KiB까지 프로세스 메모리에 보관합니다.
가장 오래된 입력의 20초 상한을 새 입력이나 재연결로 연장하지 않습니다.
상한에 도달하면 새 입력은 멈추고 기존 입력의 기한 내 복구만 계속합니다.
프로세스 종료 시 로컬 대기는 버리지만 서버 확정 점수는 유지됩니다. WS 입력을 기존 HTTP로 fallback하지 않습니다.

서버의 신규 반영 마감은 최초 DB 영속 접수부터 10초입니다. 앱 최초 전송 시각과 다릅니다.
잠금 뒤 새 DB 시각으로 판정하므로 마감 전 승인된 처리는 마감 후 커밋될 수 있습니다.
`APPLIED/REJECTED`는 최종 결과이고, `PENDING/NOT_FOUND`는 미확인입니다.
20초 경과만으로 미반영을 단정하지 않습니다. 초기 입력 기록은 자동 삭제하지 않습니다.

재연결 정산은 목록 밖 이전 `PENDING`도 `REJECTED / NOT_APPLIED_ON_RECOVERY`로 확정합니다.
서버 미접수였던 복구 ID도 최종 거절 기록을 남겨 늦은 원요청의 가산을 막습니다.
`input.result`는 해당 ID의 대기·낙관적 횟수만 정산합니다. 최종 거절은 자동 재시도하지 않습니다.

## 경쟁 OFF 중 복구 전용 연결

2026-10-27 운영 결정에 따라 `/api/v1/press-race/recovery`에 같은 Bearer 인증으로 연결합니다.
일반 경쟁 연결과 구분하며, 경쟁이 꺼져 있어도 본인의 기존 입력을 정산하는 용도입니다.
활성 서버 자격·토큰·기기·연결 검사는 그대로 적용합니다. 배포 입력 차단 중에는 이 경로도 일시 거절됩니다.

동일한 `session.init`의 `pending` 목록을 사용하되 응답은 `session.recovered`입니다.
응답의 공통 세대 봉투와 `counts`, `date`, `results`로 본인 입력만 정산하고 `inputEnabled=false`를 유지합니다.
이 응답은 `session.ready`가 아니며 입력을 재개하거나 순위를 갱신하는 신호로 사용하지 않습니다.
목록 밖 이전 `PENDING`과 미접수 복구 ID도 기존 정산 규칙을 따르고 최종 `APPLIED/REJECTED`는 유지합니다.

복구 연결은 `session.init`, `press.status`만 허용합니다. `press.submit`과 `view.change`는 거절하며
순위 구독·스냅샷을 시작하지 않습니다. 신규 가산을 위해 복구 모드를 바꾸거나 HTTP로 재전송하지 않습니다.
경쟁이 다시 공개된 뒤에는 일반 연결에서 새 초기화·정산을 마치고 입력을 재개합니다.
이 연동 변경은 #888의 실제 앱 구현·검증 완료를 의미하지 않습니다.

## 송신과 연결 확인

입력 결과와 복구 제어 JSON은 FIFO로 보존하고 순위 대기는 최신 하나만 유지합니다.
실제 소켓 송신은 직렬화하며, 결과가 계속 도착해도 최대 네 개의 연속 제어 송신 뒤 최신 순위에 차례를 줍니다.
`session.ready`는 예외적인 장벽입니다. 해당 ready가 송신되기 전에는 새 기준 순위를 보내지 않습니다.
재초기화·화면 전환은 과거 순위 대기와 추월 기준만 버리며 이미 대기 중인 입력 결과를 덮어쓰지 않습니다.

| 종료 조건 | Close code / reason | 앱의 복구 |
| --- | --- | --- |
| JWT 만료 | `1008 / AUTH_EXPIRED` | HTTP 재인증 후 새 연결 정산 |
| 같은 기기의 새 연결 승인 | `1008 / CONNECTION_REPLACED` | 현재 소켓 이외의 콜백 폐기 |
| 결과 FIFO 32개 또는 UTF-8 64KiB 초과 | `1008 / RESULT_QUEUE_OVERFLOW` | 연결 종료 후 같은 ID로 DB 결과 복구 |
| 개별 실제 송신 2초 초과 | `1008 / SEND_TIMEOUT` 또는 컨테이너 송신 실패 종료 | 연결 종료 후 같은 ID로 DB 결과 복구 |
| 정상 수신/Pong이 45초 동안 없음 | `1008 / HEARTBEAT_TIMEOUT` | 화면 활성 상태에서만 재연결 |

결과 FIFO 상한에는 현재 송신 중인 결과도 포함합니다. 32개·64KiB와 정확히 같으면 허용하며 초과하면 종료합니다.
결과를 버리고 같은 연결을 계속 사용하는 방식은 지원하지 않습니다.
서버는 15초마다 WS Ping을 보내고, 정상 명령 수신·Pong만 무응답 시간을 연장합니다.
서버의 순위·결과·Ping 송신 자체로 연결의 수신 생존 시간을 연장하지 않습니다.
완성 메시지는 16KiB 이하여야 하며 프레임 분할로 우회할 수 없습니다.

2초는 송신 전체를 감시하는 기준이며 감시는 100ms 주기입니다. JVM 스케줄링 지연까지 없다는 보장은 아닙니다.
Tomcat native 세션의 blocking send timeout 2초와 별도 watchdog을 함께 사용합니다.
종료 시 입력 자격·순위 구독·대기 참조를 송신 잠금 밖에서 해제하고 close I/O는 별도 실행합니다.
컨테이너가 먼저 송신 실패를 감지하면 `SNAPSHOT_SEND_FAILED` 또는 transport 오류 종료가 관찰될 수 있습니다.
설정 근거: [Tomcat WebSocket 설정](https://tomcat.apache.org/tomcat-11.0-doc/web-socket-howto.html).
재접속 backoff는 0.5초부터 최대 5초와 jitter를 시작값으로 사용합니다.

## 화면과 날짜의 수신 규칙

`session.ready`가 지정한 현재 소켓·서버 세대·연결 세대만 수용합니다.
`snapshotVersion`은 그 서버 세대 안의 증가 번호 문자열이며 다른 서버 세대와 숫자만 비교하지 않습니다.
화면 전환 때는 현재 `view` 이외 프레임을 무시하고 새 기준의 더 큰 버전을 적용합니다.

KST 자정에는 새 날짜의 순위·참여 상태를 완전한 기준 스냅샷으로 받습니다.
이전 기록은 유지하며 과거 입력의 `appliedDate/appliedCounts`는 해당 입력 정산에만 사용합니다.
늦은 전날 결과가 오늘 순위·참여 상태를 덮어쓰면 안 됩니다.
`baseline=true`의 추월은 항상 `0/0`입니다. 일반 갱신의 `0/0`은 알림 지우기 명령이 아니고
양수 알림만 최신 내용으로 교체합니다. 송신 성공은 앱 수신·화면 표시 완료 ACK를 뜻하지 않습니다.

## #888 실제 앱 확인 목록

다음 항목은 BE 테스트 통과로 완료 처리하지 않습니다. 담당자·기기·앱 버전·관찰 결과를 연동 검증 때 남깁니다.

- [ ] 실제 Android WS Upgrade 인증 헤더 지원과 JWT 만료 후 단일 HTTP 재발급·새 연결 초기화.
- [ ] 화면 간 연결 공유, 다른 탭·백그라운드 종료, 비활성 상태 재접속 금지와 복귀 시 무알림 기준.
- [ ] 미확인 20묶음/64KiB, 입력별 10+10초·가장 오래된 20초 상한, backoff·묶음 조회·같은 ID 유지·HTTP fallback 금지.
- [ ] 네트워크 단절·최종 거절·프로세스 종료에서 입력 차단·대기/낙관적 횟수 정산과 마지막 순위·활동 알 수 없음 표시.
- [ ] 자정·지연 ACK·이전 소켓 콜백·서버 세대 변경·화면 버전 역전에서 현재 화면 보호와 최신 추월 알림 표시.

## BE 검증의 범위

실제 인증 WS와 PostgreSQL 17/PostGIS 3.5에서 재연결 정산·진행 저장과 교체·최종 결과 보존·미접수 ID 차단·20개 경계·유휴 인증 만료를 검증합니다.
날짜·20초 이상 경과의 DB fixture와 WS 날짜 전환 모의는 실제 자정 경과 시험과 구분합니다.
제어된 소켓 시험은 FIFO·64KiB 경계·ready 장벽·최신 순위·송신 경합·watchdog의 송신 잠금 독립 종료를 관찰합니다.
실제 인증 WS에서도 결과 큐 초과 종료 뒤 같은 입력 ID의 최종 결과를 조회·재전송해 추가 가산이 없는지 확인합니다.
실제 TCP 수신 중단 시험은 작은 시험용 송수신 버퍼에서 native writer 종료·정상 연결 진행·동일 기기 복구를 확인합니다.
실제 Ping/Pong 무응답 시험과 별도로 유지하며, 운영 버퍼의 성능 결과를 뜻하지 않습니다.
nginx·blue/green·서버 전환·출시 활성화·실기기 표시 95% 1초 목표는 #924의 실제 경로 검증입니다.
