# 행정구역 지도 감정 요약 API

## 내용 필수 API 전환 (이슈 #694)

구현 대상 계약이며 개발·운영 배포 완료를 의미하지 않습니다.

| 용도 | 기존 | 내용 필수 계약 |
| --- | --- | --- |
| 익명 등록 | `POST /api/v1/emotions` | `POST /api/v2/emotions` |
| 익명·기명 선택 등록 | `POST /api/v3/emotions` | 경로 유지, 내용 필수 |
| 개별 지도 | `GET /api/v1/emotions/map` | `GET /api/v2/emotions/map` |
| 지역 요약 | `GET /api/v1/emotions/map/regions` | `GET /api/v2/emotions/map/regions` |

V2·V3 신규 등록은 `MEMO` 또는 `AUDIO`만 허용합니다. `NONE`·누락/null 유형과
null·빈 문자열·공백뿐인 메모는 400입니다. 메모는 앞뒤 공백 제거 후 최대 200 Unicode codepoint입니다.
녹음은 업로드 완료된 `audioUploadId`가 필요하며 메모와 동시에 전달하지 않습니다.
V2는 익명 등록이며, V3는 기존 JSON boolean `anonymous` 선택을 유지합니다.

V2 개별 지도의 응답·커서·삭제·차단·스냅샷 정책은 V1과 같습니다.
개별 지도와 지역 요약에는 동일한 날짜·내용·조회 범위 필터를 적용합니다(#721, #756).
내용 필터를 페이지 제한 전에 적용하며, 지역 개수와 대표 감정도 같은 내용 필터로 계산합니다.
NONE만 있는 지역은 결과에 포함하지 않습니다. V3 등록을 쓰는 앱도 V2 지도를 호출합니다.
`GET /api/v3/emotions` 전체·그룹 목록은 이미 내용 있는 감정만 반환하며 이번에 변경하지 않습니다.

V1 등록·개별 지도와 기존 데이터는 유지합니다. 지역 요약은 V1에서 V2로 옮기며 V1 지역 요약 경로는 제거합니다. 상세·수정 API에는 이번 조건을 추가하지 않습니다.
유효한 V2/V3 등록 본문으로 기존 V1 NONE의 `requestId`를 재시도하면 멱등 계약에 따라
최초 ID를 반환하며 내용을 덮어쓰지 않습니다. 새 등록에는 새 `requestId`를 사용합니다.
생성 제한은 V1·V2·V3를 합쳐 기기당 1초에 한 번입니다.

아래는 V2 지역 요약 계약입니다. ADR-0027의 기존 모든 내용 유형 집계에서,
이번 사용자 결정으로 공개 지역 요약 API를 내용 있는 감정만 집계하도록 전환합니다.


BE 구현 기준 계약이에요. 클라이언트 연동과 실제 기기 성능 검증은 아직 수행하지 않았어요.

## 요청

```http
GET /api/v2/emotions/map/regions?minLongitude=126.9&minLatitude=37.5&maxLongitude=127.1&maxLatitude=37.6&level=SIGUNGU
Authorization: Bearer <access-token>
```

| 파라미터 | 필수 | 의미 |
| --- | --- | --- |
| `minLongitude`, `maxLongitude` | 예 | 화면의 서쪽·동쪽 경도. 각각 -180~180이며 서로 달라야 해요. |
| `minLatitude`, `maxLatitude` | 예 | 화면의 최소·최대 위도. 각각 -90~90이며 최소가 최대보다 작아야 해요. |
| `level` | 예 | 클라이언트는 `SIDO`, `SIGUNGU`를 사용해요. `EMD`는 기존 요청 호환용이에요. |
| `groupId` | 조건부 | GROUP 범위의 그룹 공개 UUID 목록. `groupId=A&groupId=B`처럼 반복하며 선택한 그룹 중 하나에 속한 기록을 조회해요. 단일 값도 유지해요. |
| `startDate`, `endDate` | 조건부 | `yyyy-MM-dd`. 함께 지정하며 0001~9999년, 시작일 ≤ 종료일이에요. KST 기준 양 끝 날짜를 포함하며 둘 다 생략하면 전체 기간이에요. |
| `contentType` | 아니요 | `ALL`(기본값), `MEMO`, `AUDIO`. ALL도 NONE을 제외해요. |
| `scope` | 아니요 | `ALL`, `GROUP`, `MY`. 생략하면 groupId가 있으면 GROUP, 없으면 ALL이에요. MY는 인증된 기기가 작성한 기록이에요. |

좌표는 WGS84(EPSG:4326)를 사용하며 NaN·무한대는 허용하지 않아요.
날짜변경선을 넘는 화면은 `minLongitude > maxLongitude`로 표현해요.
SIDO·SIGUNGU는 bbox와 무관하게 해당 계층의 전국 요약을 반환해요. bbox 필수값·범위 검증은 호환을 위해 유지해요.
EMD에서만 화면과 경계의 교차로 지역을 선택해요. 지역 코드와 커서는 요청에 전달하지 않아요.
`GROUP`에는 `groupId`가 필수이고 `ALL`·`MY`에는 전달할 수 없어요.
그룹 ID의 순서와 중복은 무시해요. 그룹끼리는 OR, 날짜·내용·범위 조건과는 AND로 적용해요. 빈 값과 잘못된 UUID는 400으로 거절해요.
그룹 가입 여부로 제한하지 않으며 선택한 그룹 중 하나라도 존재하지 않거나 삭제되었으면 `404 GROUP-001`을 반환해요.
기존 bbox·level·groupId만 보내는 정상 요청은 유지하지만, 미존재 그룹을 빈 배열로 반환하던 동작은 변경돼요.

날짜·내용·범위 필터는 AND로 적용해요. 날짜는 KST 시작일 00:00 이상, 종료일 다음 날 00:00 미만이에요.
예를 들어 아래 요청은 인증된 기기의 2026-10-01~2026-10-13 메모 기록만 집계해요.

```http
GET /api/v2/emotions/map/regions?minLongitude=126.9&minLatitude=37.5&maxLongitude=127.1&maxLatitude=37.6&level=SIGUNGU&startDate=2026-10-01&endDate=2026-10-13&contentType=MEMO&scope=MY
Authorization: Bearer <access-token>
```

여러 그룹의 녹음 조회는 `contentType=AUDIO&scope=GROUP&groupId=<group-a-uuid>&groupId=<group-b-uuid>`를 전달해요.
지도 확대·축소로 개별 지도와 지역 요약을 전환할 때 같은 필터를 전달해야 해요.
서버 구현 계약이며 AN 연동·배포 완료를 의미하지 않아요.

개별 지도·목록의 커서는 선택한 그룹 전체를 보존하며 기존 2,048자 제한 없이 발급·해석해요.
기존 커서도 계속 사용할 수 있어요. 그룹을 많이 선택했다면 다음 페이지에는 `cursor`만 전달해요.
HTTP 서버·프록시의 요청 URL 길이 제한은 그대로이므로 무제한 크기의 요청을 보장하지는 않아요.

## 계층과 확대 전환

| 계층 | SGIS 코드 길이 | 집계 단위 |
| --- | --- | --- |
| `SIDO` | 2자리 | 시도. 서울특별시·경기도 등 |
| `SIGUNGU` | 5자리 | SGIS 시군구. 구가 있는 일반시는 각 구 |
| `EMD` | 8자리 | 행정동·읍·면. 법정동 기준이 아니에요. |

수원·성남·용인은 `SIGUNGU`에서 각 구로 나뉘며 시 전체를 묶는 별도 `CITY` 계층은 없어요.
클라이언트가 확대 정도에 따라 계층과 `GET /api/v2/emotions/map`의 개별 조회 전환을 선택해요.
클라이언트는 EMD 요약을 요청하지 않고, 더 확대하면 개별 지도를 사용해요. 서버는 요청한 계층을 자동으로 바꾸지 않아요.
서버의 EMD 공간 조회는 기존 요청 호환을 위해 남겨요.

## 집계 대상

- SIDO·SIGUNGU는 bbox로 지역을 선택하지 않고 전국 집계를 반환해요. 동일 계층·필터에서는 화면 위치나 크기에 따라 집계 대상이 달라지지 않아요.
- EMD 호환 경로에서만 bbox로 지역을 선택해요. 경계 일부나 경계선이 화면에 걸쳐도 지역을 선택해요.
- 총 개수와 대표 감정은 선택한 지역 전체의 같은 기록에서 계산해요. 날짜를 생략하면 전체 기간이고, 지정하면 해당 기간만 집계해요. 개별 지도 페이지 제한은 적용하지 않아요.
- `MEMO`, `AUDIO`만 포함하고 `NONE`은 제외하며, 삭제·서비스 전체 비노출 기록과 집계 조회 시점 이후 작성된 기록은 제외해요.
- 개인 감정 차단·작성자 차단을 요약에 적용하지 않아요. 기존 개별 지도·상세의 차단 정책은 유지해요.
- 날짜·내용·조회 범위 필터를 총 개수와 대표 감정에 함께 반영해요. 같은 필터여도 지역 전체 집계와 화면 내 개별 지도는 공간·개인 차단 정책 차이로 개수가 다를 수 있어요.

## 응답

Content-Type은 `application/json`, Cache-Control은 `no-cache, private`예요.
지역 요약 API의 정상 GET(200) JSON은 HTTP gzip을 지원해요. 요청의 `Accept-Encoding`에
허용된 `gzip`이 있고 원본 UTF-8 본문이 2,048바이트 이상이면 Tomcat이 본문 압축과
`Content-Encoding: gzip`·`Vary: Accept-Encoding`을 처리해요. 2,048바이트 미만이면 비압축 JSON을 받아요.
헤더 생략·`identity`·`gzip;q=0` 요청은 기존 비압축 JSON을 받아요. 압축 해제 후 JSON 구조와 값은 같아요.
다른 API·비GET·오류 응답은 이 압축 대상에서 제외해요. EMD도 같은 API를 사용하므로 포함해요.
현재 동기식 지역 요약 응답만 전송 직전 메모리에 임시 보관해 실제 바이트 길이를 확정해요.
응답 크기만큼 임시 메모리를 사용하며 응답을 재사용하는 서버 캐시는 아니에요.
이 설정은 앱의 자동 해제 동작을 전제로 하며 심사 빌드의 실기기 확인·운영 배포 완료를 의미하지 않아요.
지역 코드순으로 모든 요약을 최상위 JSON 배열로 한 번에 반환해요.
이 API는 페이지네이션을 사용하지 않으므로 `items`, `hasNext`, `nextCursor` 래퍼 필드가 없어요.
아래 지역 이름·좌표·개수는 형식 설명용 합성 값이며 실제 SGIS 값이나 운영 측정 결과가 아니에요.

```json
[
  {
    "type": "Feature",
    "id": "11010",
    "geometry": {"type": "Point", "coordinates": [127.0, 38.0]},
    "properties": {
      "level": "SIGUNGU",
      "name": "검증용 지역",
      "parentCode": "11",
      "totalCount": 3,
      "representativeState": "ANGRY"
    }
  }
]
```

`id`는 감정 ID가 아닌 SGIS 지역 코드 문자열이에요. 기존 개별 지도 응답의 숫자 ID는 유지해요.
`geometry`는 지역 내부의 고정 표시점이며 좌표 순서는 `[경도, 위도]`예요. 요청 화면 밖에 있을 수 있어요.
`parentCode`는 상위 지역 코드이며 `SIDO`에서는 null이에요. 응답에는 지역 경계 도형을 포함하지 않아요.
`totalCount`는 양수인 64비트 정수이며 0개 지역은 생략해요. 결과가 없으면 `[]`로 반환해요.
`representativeState`는 NULL을 제외한 최빈 감정이에요. 동률은 `ANGRY → DISCOURAGED → EXHAUSTED → FRUSTRATED → IRRITATED` 순서예요.
NULL 상태 기록도 총 개수에 포함하며 모든 대상의 상태가 NULL이면 대표 감정은 null이에요.

## 표시와 결과 갱신

1. 현재 화면·계층·필터와 요청 순서를 기록하고 조회해요.
2. SIDO·SIGUNGU 전국 응답 중 현재 화면 안의 표시점만 렌더링해요. 화면 밖 표시점도 해당 계층·필터의 전국 목록에 보관해요.
3. 현재 요청의 최신 성공 응답으로 활성 지역 목록을 교체해요. 이전 목록과 단순 병합하지 않아요.
4. 새 응답에서 빠진 지역은 활성 목록에서 제거해요. 삭제 후 0개가 된 지역을 예전 캐시로 다시 표시하지 않아요.
5. 다른 계층·필터·화면의 결과나 늦게 도착한 이전 요청의 응답으로 현재 결과를 덮어쓰지 않아요.

이 규칙은 클라이언트 연동 시 적용할 계약이며 클라이언트 구현을 완료했다는 의미는 아니에요.
서버 응답 캐시는 추가하지 않았어요. 앱 캐시를 적용할 때 전국 결과의 식별자는 계층·필터·그룹·인증 기기이며 bbox는 포함하지 않아요.
HTTP `no-cache, private`는 유지하며 앱의 명시적 데이터 캐시와는 별개예요.

## 계측

`regions_service`는 기존 v2 서비스 호출 전체, `regions_summary`는 감정 집계 구간이에요.
SIDO·SIGUNGU에서는 `regions_intersection`, `regions_boundaries`가 기록되지 않으며 공간 조회 0초로 해석하지 않아요.
계층별 지역 메타데이터 조회 시간은 별도 단계로 계측하지 않으며 서비스 전체 시간에 포함돼요.

## 오류와 공개 준비

| 상태 | 코드 | 의미 |
| --- | --- | --- |
| 400 | `COMMON-001` | 필수값 누락 또는 잘못된 영역·계층·날짜·내용·범위·그룹 UUID |
| 401 | `AUTH-001` | 유효한 인증이 없음 |
| 404 | `GROUP-001` | 존재하지 않거나 삭제된 그룹 |
| 503 | `EMOTION-013` | 지역 요약 준비가 완료되지 않음 |

오류 본문은 공통 `{"code":"…","message":"…"}` 형식이에요. 실패 응답을 정상적인 빈 목록으로 처리하지 않아요.
후보 지역이 없는 화면도 준비 검사를 거쳐요. 경계와 백필 검증이 완료되어야 요약을 제공해요.
[경계 적재·백필 절차](../../scripts/regions/README.md)를 사용하며 개발·운영 적재, 백필 실행과 배포는 별도 승인 대상이에요.
서버 응답·전송량·반환 객체 수와 실기기 CPU·메모리·프레임은 구분해서 검증하며 실제 개선 효과는 아직 측정하지 않았어요.
