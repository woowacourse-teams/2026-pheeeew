# ADR-0020: 구글 복호화 호출에 프로젝트 단위 하루 예산을 둔다

## Status

Accepted (2026-09-13)

## Context

- 구글 Play Integrity 표준 티어는 하루 10,000건 무료예요. 소진되면 구글이 거절하고 그때부터 정상 등록도 전부 실패해요.
- nginx 의 IP 당 제한과 challenge 당 시도 상한(ADR-0018)은 요청 하나하나를 묶지만, **분산된 요청이 합쳐서 할당량을 소진시키는 것**은 막지 못해요.
- 우리 날짜 경계와 구글의 할당량 초기화 시각대가 같은지 확인하지 못했어요.

## Decision

날짜별 예산 행을 두고 `INSERT ... ON CONFLICT DO UPDATE ... WHERE call_count < ?` 한 문장으로 증가시켜요. 영향 행이 0이면 구글을 부르지 않고 거절하며, 기본 예산은 하루 3,000회예요.

## Alternatives

- 예산을 메모리에 두기 — 배포마다 초기화되고 인스턴스가 늘면 실제 한도가 조용히 N배가 돼요. 고장에 신호가 없어서 선택하지 않았어요.
- 예산을 Redis 에 두기 — 새 의존성이 필요하고, 휘발되면 한도가 사라져요.
- 예산 없이 구글의 거절에 맡기기 — 소진 시점을 우리가 모르고, 남은 할당량도 보존되지 않아요.

## Consequences

- (+) 할당량이 소진되기 전에 **우리가 먼저 멈춰요.** 원인이 분명하고 남은 할당량이 보존돼요.
- (-) **예산을 넘으면 정상 등록도 함께 막혀요.** 우리가 스스로 만든 장애이고, 회복은 날짜가 바뀌거나 예산을 올리는 것뿐이에요.
- (-) **예산 3,000은 관측 전에 정한 수예요.** 구글 10,000 에서 날짜 경계가 어긋나는 최악을 2배로 보아 상계 5,000 을 잡고 다시 40% 를 덜어낸 값이고, 실제 호출량을 본 적이 없어요.
- (-) 구글 호출마다 DB 쓰기가 한 건 늘어요. ADR-0018 의 시도 수 증가와 합하면 호출당 두 건이에요.
- (=) 예산 행은 UTC 날짜로 갈라요. 한국 시각으로는 **오전 9시에 예산이 풀려요.** 저녁에 소진되면 밤 시간대 전체를 소진 상태로 보내요.
- (=) **카운터 증가는 `REQUIRES_NEW` 로 자기 트랜잭션에서 커밋해요.** 바깥에 트랜잭션이 없다는 사실에 방어를 걸지 않으려는 것이에요. 이 결정은 ADR-0004 를 바꾸지 않고, 그 결정에 의존하지 않게 만들어요.
- (=) `REQUIRES_NEW` 는 바깥 트랜잭션이 있을 때 커넥션을 하나 더 잡아요. 지금 등록 경로에는 바깥 트랜잭션이 없어서 추가 점유가 없지만, 생기면 스레드당 두 개가 돼요. 풀 기본값은 10이에요.
- (=) 예산 소진은 `DEVICE-007`(503) 으로 응답해요. 구글 장애와 클라이언트 행동이 같기 때문이고, 운영에서는 지표 사유 `CALL_BUDGET_EXHAUSTED` 로 갈라 봐요.
- 재검토: 실제 호출량을 관측한 뒤 예산을 정해요. 무결성 증명을 강제하면 호출량이 크게 늘어나므로 그 전에 반드시 다시 봐야 해요.

## Compliance

- 예산을 넘은 요청이 구글을 호출하지 않고, 카운터도 상한에서 멈추는지 확인해요.
- 동시 요청에서 예산 카운터가 정확한지 확인해요.
- **바깥 트랜잭션이 롤백돼도 카운터가 남는지 확인해요.** `REQUIRES_NEW` 를 떼면 이 테스트가 깨져요.
- 예산 소진 응답이 `503` 과 `Retry-After` 를 함께 내는지 확인해요.
