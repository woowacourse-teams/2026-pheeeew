# ADR-0018: challenge 한 건이 낼 수 있는 구글 복호화 호출을 5회로 묶는다

## Status

Accepted (2026-09-13)

## Context

- 기기 등록은 인증 없이 열려 있어요. `attestation.token` 을 실으면 서버가 구글 복호화 API 를 불러요.
- challenge 사전 조회는 읽기 전용이라 복호화가 실패해도 challenge 가 남았어요(ADR-0016). 그래서 challenge 한 건으로 구글 호출을 무한히 낼 수 있었어요.
- nginx 에 IP 당 요청 수 제한을 두었지만 challenge 하나를 반복해서 쓰는 것은 막지 못해요.
- 구글 Play Integrity 표준 티어는 하루 10,000건 무료이고, 소진되면 정상 등록도 전부 실패해요.

## Decision

구글을 부르기 전에 challenge 행의 시도 수를 조건부 UPDATE 로 증가시켜요. 영향 행이 0이면 거절하고, 상한은 5로 둬요.

## Alternatives

- challenge 를 예약하고 실패 시 해제 — 상태와 경합이 늘어나요. 시도 수 증가는 조건부 UPDATE 한 문장으로 끝나요.
- 소모 시점을 앞당겨 복호화 전에 challenge 를 없애기 — 구글 장애나 일시적 오류로도 challenge 가 사라져 정상 사용자가 재시도할 수 없어요.
- IP 당 제한만 두기 — 같은 challenge 를 반복해서 쓰는 것을 묶지 못해요.

## Consequences

- (+) challenge 한 건이 구글 호출 5회를 넘지 못해요. 형태 검사에서 걸린 요청은 시도조차 소모하지 않아요.
- (-) **상한 5는 관측 전에 정한 수예요.** 정상 사용자가 몇 번 재시도하는지 알지 못한 채로 정했어요. 앱에 무결성 증명 코드가 아직 없어서 재시도 정책도 정해지지 않았어요.
- (-) 구글 호출마다 DB 쓰기가 한 건 늘어요.
- (=) `consume()` 은 시도 수를 보지 않아요. 5번째 시도가 정상 성공했을 때 소모까지 막으면 구글이 정품으로 판정한 요청을 거절하게 돼요.
- 재검토: 앱이 증명을 붙이고 재시도 정책이 정해지면 상한을 다시 정해요. 실제 시도 분포를 본 뒤에 판단해요.

## Compliance

- 상한을 넘은 요청이 구글을 호출하지 않는지 실측으로 확인해요.
- 동시 요청에서 시도 수가 정확한지 확인해요.
- 형태 검사에서 걸린 요청이 시도를 소모하지 않는지 확인해요.
- 바깥 트랜잭션이 롤백돼도 시도 수가 남는지 확인해요. 카운터는 `REQUIRES_NEW` 로 자기 트랜잭션에서 커밋해요.
