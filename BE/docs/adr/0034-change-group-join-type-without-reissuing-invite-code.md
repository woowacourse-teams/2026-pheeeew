# ADR-0034: 그룹장이 가입 방식을 전용 경로로 바꾸고 초대 코드는 그대로 둔다

## Status

Accepted (2026-10-11)

## Context

- ADR-0033이 공개, 비공개 구분을 도입했지만 만든 뒤에 바꾸는 길은 두지 않았어요. 잘못 고르면 지우고 다시 만들어야 했어요.
- 초대 코드는 가입 방식과 무관하게 생성 시 항상 발급되고, 공개 그룹도 코드로 가입할 수 있어요. **공개는 "코드 없이도 가입할 수 있다" 는 뜻이고 "코드가 없다" 는 뜻이 아니에요.**
- 생성 요청은 `joinType` 을 생략하면 비공개로 읽어요(ADR-0033). 변경에서 같은 의미를 쓰면 이름만 바꿔도 공개 그룹이 비공개로 돌아가요.
- 그룹 수정, 삭제, 초대 코드 재발급은 모두 그룹장만 할 수 있어요.

## Decision

`PUT /api/v2/groups/{groupId}/join-type` 을 두고 **그룹장만** 가입 방식을 바꿀 수 있게 하며, `joinType` 을 필수로 받아요. **전환은 초대 코드와 기존 멤버를 건드리지 않아요.** 같은 값으로 바꾸는 것도 성공으로 둬요.

## Alternatives

- `PUT /api/v2/groups/{groupId}` 에 `joinType` 을 더하기 — 생성의 "생략하면 비공개" 와 같은 의미를 쓰면 이름만 바꿔도 공개 그룹이 닫혀요. "생략은 현상 유지" 로 가르면 한 필드가 두 뜻을 갖게 돼요.
- 비공개로 바꿀 때 초대 코드를 자동 재발급 — 공개였던 동안 퍼진 코드를 끊지만, 그 코드로 공유한 링크와 메시지가 전부 죽어요.
- 같은 값으로 바꾸면 409 — 재시도와 실제 중복을 구분할 수 없어요.

## Consequences

- (+) 그룹을 지우지 않고 가입 방식을 되돌릴 수 있어요. 기존 멤버가 영향을 받지 않아요.
- (+) `joinType` 을 필수로 받으므로 "생략하면 무엇인가" 를 정할 필요가 없어요.
- (-) **공개였던 동안 퍼진 초대 코드는 비공개로 바꿔도 계속 통해요.** 끊으려면 `POST /api/v2/groups/{groupId}/invite-code` 를 따로 불러야 해요.
- (-) 전환과 코드 없는 가입이 겹치면 `READ COMMITTED` 에서 한 명이 비집고 들어올 수 있어요. 그룹장이 멤버를 뺄 수단이 없어 그 멤버는 남아요. 기존 `reissueInviteCode` 와 `joinByInviteCode` 사이에도 같은 틈이 있어요.
- (=) 경로를 하나 더 두는 쪽을 골랐어요. `POST /api/v2/groups/{groupId}/invite-code` 가 같은 모양의 선례예요.
- 재검토: **그룹장이 멤버를 내보내는 기능이 생기면** 위 경합의 피해를 되돌릴 수 있으니 전환을 더 엄격하게 잠글지 다시 판단해요. 비공개 전환 시 코드 자동 재발급을 원하는 요구가 나오면 그때 함께 봐요.

## Compliance

- 전환이 가입 경로를 실제로 바꾸는지는 `GroupServiceIntegrationTest` 가 고정해요. 전환 전후로 같은 코드 없는 가입을 호출해 한쪽만 통과하는 것을 봐요.
- 전환이 초대 코드와 기존 멤버를 건드리지 않는지도 같은 곳에서 고정해요.
- 그룹장이 아닌 멤버와 비멤버가 각각 `GROUP-003`, `GROUP-008` 을 받는지 고정해요.
