# ADR-0015: 무결성 증명은 토큰이 있을 때만 검증한다

## Status

Accepted (2026-09-13)

## Context

- 이미 배포된 앱은 `attestation.token` 을 보내지 않아요. 등록 계약이 `null` 을 허용하고 있어요.
- 검증을 강제하면 배포하는 순간 그 앱들이 전부 등록에 실패해요. 앱에는 토큰을 받아올 코드 자체가 없어서 "구형 앱만 깨진다" 가 아니라 전면 쓰기 중단이에요.
- 이슈는 "운영 프로필에서 검증을 비활성화할 수 없도록 한다" 를 완료 조건으로 적었어요. 그런데 그 설정을 지금 넣으면 전부 거절하거나 전부 통과하게 되고, 둘 다 틀려요.
- 설정만으로는 되돌릴 수 없는 잠금을 만들 수 없어요. 환경변수가 yml 리터럴을 이기므로 운영 yml 에 `true` 를 박아도 뒤집혀요.

## Decision

`token` 이 없으면 검증하지 않고 통과시키고, 있으면 검증해 실패 시 거절해요. 앱 전환이 끝난 뒤 `null` 을 거절하도록 켜는 잠금은 설정이 아니라 코드 상수로 둬요.

## Alternatives

- 지금 강제 — 배포 즉시 전면 쓰기 중단이라 선택하지 않았어요.
- 항상 통과하는 검증기를 두고 강제를 켜기 — 완료 조건이 아무것도 검증하지 않는 상태에서 충족돼요. 나중에 진짜 검증기가 들어올 때 켜는 동작이 없어 배포 게이트 없이 조용히 거절이 시작되므로 선택하지 않았어요.
- 강제 여부를 설정으로만 두기 — 환경변수가 yml 을 이기므로 되돌릴 수 없는 잠금이 성립하지 않아 선택하지 않았어요.

## Consequences

- (+) 구형 앱과 신형 앱이 전환기에 공존해요. 신형 앱은 배포 즉시 실제로 검증돼요.
- (+) 켜기는 설정 한 줄이고 되돌리기는 리뷰를 거친 코드 변경이에요. 비대칭이 의도예요.
- (-) **이슈 완료 조건 두 개가 충족되지 않아요.** 강제가 꺼져 있으므로 "운영에서 비활성화할 수 없다" 와 "기본값은 활성" 이 모두 거짓이에요. 이 결정으로 #259 를 닫을 수 없어요.
- (-) **ADR-0004 가 약속한 동시 등록 보장이 토큰을 실은 경로에서 깨져요.** 같은 challenge 를 실은 토큰으로 동시에 등록하면 challenge 조건부 소모에서 갈려 한 건만 성공하고 나머지는 오류를 받아요. 실측했어요 — 6건 동시 요청에서 성공 1건, 나머지 5건이 400 이고 리프레시 토큰은 1개예요. 증명이 없는 경로는 여전히 6건 모두 성공해요.
- (=) 강제를 켜는 시점에 ADR-0004 를 함께 판단해야 해요. 지금은 토큰을 보내는 앱이 없어 도달할 수 없는 경로예요.
- (=) 개발 환경에서 검증을 건너뛰는 설정은 운영 프로필에서 켜면 부팅이 실패해요. 강제 상수를 켜면 그 우회도 모든 프로필에서 막혀요.
- 재검토: 앱이 토큰을 보내기 시작하고 판정 분포를 확인한 뒤 강제 시점을 정해요. 그때 ADR-0004 의 보장 범위도 함께 정리해요.

## Compliance

- `token` 이 없는 기존 본문이 그대로 성공하는지 통합 테스트로 확인해요.
- 운영 프로필에서 우회 설정을 켜면 부팅이 실패하는지 확인해요.
- 동시 등록에서 증명을 실은 경로와 실지 않은 경로의 결과가 서로 다른 것을 테스트로 고정해요. 강제를 켜거나 ADR-0004 대로 고치면 그 테스트가 깨져서 결정이 드러나요.
