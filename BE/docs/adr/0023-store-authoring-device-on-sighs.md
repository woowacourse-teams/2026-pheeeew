# ADR-0023: 한숨에 작성 기기를 저장한다

## Status

Accepted (2026-09-14)

## Context

- 사용자 차단을 하려면 서버가 작성자를 알아야 해요. 지금까지 `sighs` 에는 작성자가 없었어요.
- ADR-0006 이 위치를 반경 300m 원 안 면적 균등 추출로 두 번(앱, 서버) 옮겨요. **그 결정의 `(-)` 가 이미 "반복 좌표를 연결해 평균내는 것"을 경고했어요.** `device_id` 가 그 **연결 수단**을 시스템 안에 만들어요.
- 40만 표본 몬테카를로로 실측했어요. 축당 표준편차는 원 하나에 150m, 두 번 합치면 212.1m 예요. 같은 장소의 한숨 n 건을 평균내면 그만큼 줄어요.

| n | 실제 위치와의 거리 중앙값 |
| --- | --- |
| 1 | 267m |
| 4 | 127m |
| 25 | **50m** |
| 100 | **25m** |

- **격자 방식이었다면 하한이 있었어요.** 결정적 양자화라 평균내도 셀 크기 밑으로 못 갔어요. 독립 원에는 하한이 없어요.
- `POST /api/v1/sighs` 가 인증 없이 열려 있고, 기존 한숨에는 채울 값이 없어요.

## Decision

`sighs.device_id` 를 `NULL` 허용으로 두고 `devices(id)` 를 참조해요. `POST /api/v2/sighs` 로 들어온 한숨만 채우고 응답에는 내보내지 않아요.

## Alternatives

- 저장하지 않고 한숨 차단만 유지 — 익명성이 그대로지만 사용자 차단을 만들 수 없어요. 이슈가 요구한 기능이에요.
- `NOT NULL` 로 두기 — v1 경로가 열려 있어 성립하지 않고, 기본값 없이 추가하면 기존 행에서 마이그레이션이 실패해요.
- 기존 한숨에 유령 기기를 백필 — 한숨마다 다른 기기를 물리면 차단 결과가 한숨 차단과 같아 얻는 것이 없고, 하나에 몰면 그것을 차단한 사용자에게 과거 한숨이 통째로 사라져요.

## Consequences

- (+) 사용자 차단이 가능해져요. 차단 뒤 그 기기가 새로 올린 한숨까지 걸러요.
- (-) **같은 기기의 한숨을 모으면 생활 반경이 드러나요.** 25건이면 50m 예요. ADR-0006 이 각각 안전하다고 본 좌표들이 연결되면 안전하지 않아요. **두 결정은 각각 옳았지만 합치면 그렇지 않아요.**
- (-) DB 를 읽을 수 있는 쪽이 그 연결을 볼 수 있어요. 응답을 막는 것으로는 이 위험이 줄지 않아요.
- (=) 기존 한숨과 v1 한숨은 `NULL` 이라 사용자 차단 대상이 되지 않아요. 한숨 차단으로는 가릴 수 있어요.
- (=) **개인정보처리방침을 갱신해야 해요.** 무엇을 연결해 저장하는지가 달라졌어요.
- 재검토: v1 등록 경로를 닫을 때 `NULL` 행 처리와 `NOT NULL` 전환을 함께 판단해요. 한 기기의 한숨 수가 실제로 얼마나 쌓이는지 관측한 뒤 보관 기간을 정해야 해요.

## Compliance

- 응답과 로그 어디에도 작성자가 나가지 않는 것을 확인해요.
- `NULL` 인 한숨이 조회에서 사라지지 않는 것을 확인해요(ADR-0024).
