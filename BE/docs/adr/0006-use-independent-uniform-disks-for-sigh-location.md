# ADR-0006: 클라이언트와 서버에서 독립적인 균등 원 이동을 적용한다

## Status

Accepted (2026-09-07). ADR-0002를 대체해요. 구현 방향을 채택한 것이며 클라이언트 전환·실제 앱 검증·배포 승인을 뜻하지 않아요.

## Context

- 같은 300m 격자에서 한숨이 누적되면 사각형의 윤곽이 드러났어요. 격자 중심을 유지한 가우시안·강도장과 격자를 없앤 모델을 합성 좌표로 비교했어요.
- 사용자가 팀의 선호를 전달하고 [E009](../experiments/e009-location-pipeline/results/2026-09-07/README.md)의 ②, 클라이언트와 서버의 이중 원 이동으로 진행하도록 승인했어요. 독립 블라인드 평가나 실제 앱 검증을 통과했다는 뜻은 아니에요.
- 실제 위치를 서버로 보내지 않는 원칙과 최초 저장 위치를 재시도·조회에서 유지하는 계약은 지켜야 해요.

## Decision

클라이언트는 실제 위치를 EPSG:5179로 변환한 뒤 반경 300m 원 내부에서 면적 균등 추첨하고, 그 근사 좌표만 WGS84로 서버에 보내요. 서버는 받은 근사 좌표에 독립적인 반경 300m 균등 원 이동을 적용해 최종 위치를 `geometry(Point, 4326)`으로 저장해요. 격자 재정렬·가우시안·경계 clamp를 적용하지 않아요.

두 단계 모두 독립 균등 난수 `U,V ∈ [0,1)`에 `r=300√U`, `θ=2πV`를 적용해요. 서버는 `SecureRandom`을 사용하고 클라이언트도 플랫폼의 보안 난수원을 사용해요. 좌표·시각·사용자 식별자로 seed를 만들거나 서버와 난수열을 공유하지 않아요.

새 등록마다 새 `requestId`와 근사 좌표를 만들고 같은 등록의 재시도에는 둘 다 재사용해요. 서버는 요청 좌표가 달라도 같은 `requestId`의 최초 저장 결과를 반환해요. 동시 요청에서 생성된 후보가 여러 개여도 DB에 먼저 저장된 한 위치만 최종 결과가 돼요. 기존 저장 위치는 재계산하지 않아요. 요청 좌표 원문은 별도로 저장하지 않아요.

## Alternatives

- 격자 중심 + tapered Gaussian D 또는 강도장 E — 기존 실험으로 보존해요. 격자 입력을 유지하며 경계를 완화하는 복잡한 후보 대신, 이번에는 격자를 없애고 이중 원 이동을 선택했어요.
- 실제 위치 전송 + 서버 단일 원 이동 — 서버 계산은 같지만 실제 위치를 처리하게 되고 단일 장소의 원 경계도 더 뚜렷해 선택하지 않았어요.
- 클라이언트 원 이동만 적용 — 서버 이동까지 포함한 E009의 ②와 다른 분포여서 선택하지 않았어요.

## Consequences

- (+) 격자 경계 없이 단순한 두 원 이동으로 합성 단일 장소의 외곽 밀도가 완만해져요. 서비스에 실험용 강도장·가우시안 엔진을 넣지 않아요.
- (-) 최종 위치는 실제 위치에서 EPSG:5179 평면 기준 최대 600m까지 멀어져요. 지표면 거리의 엄밀한 600m 상한은 아니며 투영·수치 오차가 있어요.
- (-) 근사 좌표도 위치 정보예요. 반복 공개 좌표를 연결해 평균내면 중심을 추정할 수 있어요. 보안 난수와 이중 원만으로 익명성이나 형식적 프라이버시를 보장하지 않아요.
- (=) 서버는 좌표만으로 클라이언트가 무작위화했는지 판별할 수 없어요. 실제 위치·요청 근사 좌표를 모바일 로그·서버 로그·분석·오류 수집에 남기지 않도록 별도로 점검해야 해요.
- 재검토: 구형 앱 혼재, 반복 관측 정책, 허용 이동 거리나 대한민국 밖 서비스 지역이 달라질 때 다시 판단해요. 시간 감쇠·노출 수명·줌 정책은 이번 결정에 포함하지 않아요.

## Compliance

- v1/v2의 JSON 필드는 유지하지만 좌표 의미는 비호환 변경이에요. 구형 앱은 자동으로 ②가 되지 않아요. 구형 앱 차단·강제 업데이트 또는 버전 분리 등 전환 방식을 팀이 결정하기 전에는 배포하지 않아요. 이 변경에는 자동 배포 차단 장치나 버전 분기가 없어요.
- 클라이언트 변경 완료와 공통 좌표 계산 검증, PR 전 실제 앱 화면 확인을 배포 전제 조건으로 둬요. 서버 테스트 통과만으로 이를 완료 처리하지 않아요.
- 순수 계산의 면적 균등성·반경·방향을 결정적으로 검증하고 PostgreSQL 17·PostGIS 3.5에서 좌표 변환·저장·재시도·동시 응답 위치 일치를 검증해요. [ADR-0004](0004-skip-transaction-on-idempotent-save.md)의 트랜잭션 경계는 유지해요.

클라이언트 계산·재시도·전환 체크리스트는 [300m 균등 원 가이드](../client/300m-uniform-disk.md)를 따라요.
