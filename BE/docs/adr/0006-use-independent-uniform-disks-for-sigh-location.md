# ADR-0006: 클라이언트와 서버에서 독립적인 균등 원 이동을 적용한다

## Status

Accepted (2026-09-07). ADR-0002를 대체해요. 구현 방향을 채택한 것이며 클라이언트 전환·실제 앱 검증·배포 승인을 뜻하지 않아요.

## Context

- 같은 300m 격자에서 한숨이 누적되면 사각형의 윤곽이 드러났어요. 격자 중심을 유지한 가우시안·강도장과 격자를 없앤 모델을 합성 좌표로 비교했어요.
- 합성 위치 비교에서는 클라이언트와 서버가 각각 무작위로 이동하는 방식이 단일 원보다 외곽 밀도를 부드럽게 만들었어요. [최종 비교 요약](../decisions/map-star-location-evidence.md)에 그림·수치와 한계를 정리했어요. 실제 앱에서 같은 인상을 주는지는 별도로 확인해야 해요.
- 실제 위치를 서버로 보내지 않는 원칙과 최초 저장 위치를 재시도·조회에서 유지하는 계약은 지켜야 해요.

## Decision

클라이언트는 실제 위치 주변 반경 300m 원 안에서 무작위로 고른 근사 좌표만 서버에 보내요. 서버도 받은 좌표 주변 반경 300m 원 안에서 독립적으로 최종 표시 위치를 골라 저장해요. 원의 중심이나 가장자리에 치우치지 않도록 원 내부 면적에 균등하게 분포시키고, 양쪽에서 서로 독립적인 보안 난수를 사용해요.

격자 중심으로 맞추는 단계를 없애고, 두 번의 단순한 원 이동으로 별 무리의 바깥 밀도가 완만해지는 효과를 얻기 위해 선택했어요. 정확한 좌표 변환·계산식·난수 처리 규칙은 [클라이언트 구현 가이드](../client/300m-uniform-disk.md)에 둬요.

새 등록마다 새 요청 식별자와 근사 좌표를 만들고, 같은 등록의 재시도에는 둘 다 재사용해요. 서버는 같은 요청 식별자의 최초 저장 위치를 유지하고 기존 별도 다시 배치하지 않아요. 요청 좌표 원문은 별도로 저장하지 않아요.

## Alternatives

- 격자 중심을 유지하고 가우시안 분포나 위치별 밀도 조절을 추가하는 방식 — 검토한 코드와 결과는 보존해요. 격자 입력을 유지하면서 계산을 복잡하게 하는 대신, 입력의 격자 자체를 없애는 단순한 방식을 선택했어요.
- 실제 위치 전송 + 서버 단일 원 이동 — 서버 계산은 같지만 실제 위치를 처리하게 되고 단일 장소의 원 경계도 더 뚜렷해 선택하지 않았어요.
- 클라이언트 원 이동만 적용 — 같은 장소에서 반복 생성하면 단일 원의 선명한 경계가 남아요. 더 넓게 퍼지는 비용을 감수하고 두 번 이동하는 방식을 선택했어요.

## Consequences

- (+) 격자 경계 없이 단순한 두 원 이동으로 합성 단일 장소의 외곽 밀도가 완만해져요. 서비스에 실험용 강도장·가우시안 엔진을 넣지 않아요.
- (-) 최종 위치는 실제 위치에서 EPSG:5179 평면 기준 최대 600m까지 멀어져요. 지표면 거리의 엄밀한 600m 상한은 아니며 투영·수치 오차가 있어요.
- (-) 근사 좌표도 위치 정보예요. 반복 공개 좌표를 연결해 평균내면 중심을 추정할 수 있어요. 보안 난수와 이중 원만으로 익명성이나 형식적 프라이버시를 보장하지 않아요.
- (=) 서버는 좌표만으로 클라이언트가 무작위화했는지 판별할 수 없어요. 실제 위치·요청 근사 좌표를 모바일 로그·서버 로그·분석·오류 수집에 남기지 않도록 별도로 점검해야 해요.
- 재검토: 구형 앱 혼재, 반복 관측 정책, 허용 이동 거리나 대한민국 밖 서비스 지역이 달라질 때 다시 판단해요. 시간 감쇠·노출 수명·줌 정책은 이번 결정에 포함하지 않아요.

## Compliance

- v1/v2의 JSON 필드는 유지하지만 좌표 의미는 비호환 변경이에요. 구형 앱은 계속 격자 중심을 보내므로 서버만 바꿔서는 선택한 이중 원 분포가 되지 않아요. 구형 앱 차단·강제 업데이트 또는 버전 분리 등 전환 방식을 팀이 결정하기 전에는 배포하지 않아요. 이 변경에는 자동 배포 차단 장치나 버전 분기가 없어요.
- 서버 PR을 먼저 준비하고 클라이언트 팀원이 새 계약을 적용해요. 클라이언트 변경 완료·공통 좌표 계산·실제 앱 화면 확인은 배포 전제 조건이며 서버 테스트로 대체하지 않아요.
- 순수 계산의 면적 균등성·반경·방향을 결정적으로 검증하고 PostgreSQL 17·PostGIS 3.5에서 좌표 변환·저장·재시도·동시 응답 위치 일치를 검증해요. [ADR-0004](0004-skip-transaction-on-idempotent-save.md)의 트랜잭션 경계는 유지해요.

클라이언트 계산·재시도·전환 체크리스트는 [300m 균등 원 가이드](../client/300m-uniform-disk.md)를 따라요.

저장소 루트 기준 `BE/src/test/java/com/pheeeew/sigh/experiment/e001/`에 이전 모델·실행기, `BE/src/test/java/com/pheeeew/sigh/infra/E010ProductionCoordinatesTest.java`에 실제 서버 비교 실행기, `BE/docs/experiments/`에 프로토콜·원본 CSV·그림·검증 도구가 있어요. 이 파일들은 서버 PR에 포함하지 않고 제품 코드·회귀 테스트·위 비교 요약만 포함해요.

보존 브랜치가 원격에 게시된 뒤에는 해당 브랜치를 받아 전환하고 위 경로의 파일을 열어 확인해요. 작업 중인 변경사항을 먼저 안전하게 보관해요. 구체적인 확인 순서와 주요 파일은 [비교 요약](../decisions/map-star-location-evidence.md#원본-보존과-재현)을 따라요. 2026-09-07 분리 시점에는 로컬 Git에만 보존했어요.
