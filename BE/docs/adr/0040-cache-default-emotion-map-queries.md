# ADR-0040: 기본 지도 조회는 JVM 캐시를 사용하고 쓰기·재집계를 직렬화한다

## Status

Accepted (2026-10-20). ADR-0039의 캐시 미도입 결정을 기본 지도 조회 범위에서 변경해요.
구현 검증은 완료했으며 배포·운영 성능 검증은 아직 하지 않았어요.

## Context

- 기본 전국 지역 요약과 핀 후보를 반복 조회하지만 원본은 DB에 보관해요.
- 재집계와 증분 갱신이 겹치면 중복 집계·누락·삭제 전 결과의 재게시가 생길 수 있어요.
- 단일 JVM을 전제로 등록은 최대 3초 지연을 허용하되 수정·삭제 성공 후 시작한 조회에는 즉시 반영해야 해요.

## Decision

기본 전국 지역 요약과 경량 핀 후보를 Caffeine에 보관하고, 캐시를 사용할 수 없으면 기존 SQL로 응답해요.

기준선과 증분의 인계 순서를 단순하게 유지하도록 일반 쓰기와 재집계를 저장에 필요한 DB 조회·트랜잭션 시작 전부터 실제 완료까지 직렬화하고, DB 커밋 후에만 캐시 기여분을 반영해요.
녹음 업로드 사전 조회·S3 확인은 잠금과 저장 트랜잭션 밖에서 수행하고, 업로드 행을 잠근 뒤 소유자·만료·연결 상태와 확인한 메타데이터를 재검증해요.
외부 트랜잭션이 있으면 사전 조회는 참여하고 S3 호출 동안만 중단해요. 동시 요청의 S3 확인은 중복될 수 있어요.

등록 스냅샷은 첫 변경부터 1초 동안 모아 게시하되 3초 이상 지연되면 SQL로 응답하고, 수정·일반 삭제는 새 스냅샷을 교체한 뒤 성공을 반환해요.

적용 범위·핀 상한·차단·커서·복구 정책: [지도 조회 계약](../client/emotion-region-map.md).

## Alternatives

- 매 요청 SQL: 정합성 처리가 단순하지만 반복 조회 비용이 남아 장애 시 대체 경로로 유지해요.
- 무효화만 사용: 진행 중인 재집계·과거 배치의 재게시를 별도로 막아야 해 세대·작업 동일성 검사를 함께 사용해요.
- 처음부터 병렬 쓰기: 쓰기 대기를 줄일 가능성은 있지만 기준선 포함 범위와 증분 중복을 조정해야 해 측정 뒤 재검토해요.
- Outbox·공유 캐시·영속 집계: 전달 복구·다중 JVM 조정에 도움이 되지만 이번에는 DB에서 재생성 가능한 파생 캐시로 범위를 제한해요.

## Consequences

- (+) 반복 집계·후보 SQL을 줄이고, 게시된 불변 스냅샷 조회는 긴 쓰기 잠금을 기다리지 않아요.
- (-) 긴 재집계는 쓰기를 기다리게 하며 후보 복사·정렬·순차 탐색과 스냅샷 보관 비용이 남아요.
- (=) 이미 열린 외부 트랜잭션은 잠금 역전을 피하도록 긴 JVM 잠금을 우회하고 완료까지 캐시 대신 SQL을 사용한 뒤 복구해요.
- (=) 재시작 시 DB에서 다시 만들며 10분 정기 보정으로 외부 변경을 보정해요. 캐시 적중에도 검증·차단·스탬프 SQL은 남아요.
- 재검토: 잠금 대기·재생성 시간·SQL 대체율·힙 사용량·핀 탐색 비용을 측정해 병렬화·인덱스·상한을 조정하고 JVM 수가 늘면 조정 방식을 다시 설계해요.

## Compliance

PostgreSQL 17/PostGIS 3.5에서 재집계 중 등록·삭제 인계, 외부 트랜잭션 롤백, 과거 작업의 재게시 방지를 검증해요.
1초 배치·3초 기한은 제어 가능한 시계·실행기로, 인증·응답 계약은 HTTP 통합 테스트로 확인해요.
