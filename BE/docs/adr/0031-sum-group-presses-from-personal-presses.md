# ADR-0031: 그룹 프레스를 개인 프레스의 멤버십 조인 합산으로 구한다

## Status

Accepted (2026-10-07)

## Context

- 그룹 프레스는 `group_daily_presses` 에 `(group_id, press_date, state)` 로 직접 쌓였어요. 한 그룹의 모든 사람이 행 하나를 다투고, 묶음 전송(#637)을 넣어도 한 요청이 감정 다섯 행을 전부 잠가 완전히 직렬이 돼요(#631, #637).
- #649 로 개인 프레스가 `(press_date, region_code, state, device_id)` 에 쌓이고 있어요. 그 결정은 ADR 로 남기지 않았어요. 기기를 키에 두면 같은 지역, 같은 감정을 동시에 눌러도 서로 다른 행이라 경합이 없다는 것을 확인했어요.
- `group_members` 는 `uk_group_members_active (group_id, device_id) WHERE left_at IS NULL` 이라 **기기가 여러 그룹에 동시에 속할 수 있어요.**
- 개인 프레스는 위치가 필수이고 지역 미배정이면 거부돼요(ADR-0028). 그룹 프레스는 지금까지 위치 없이 눌렸어요.
- 공동 순위 규칙(1, 2, 2, 4)은 `GroupRankingService.rank` 자바 코드 한 벌이고 다섯 지점이 그것을 써요.
- [이슈 #658](https://github.com/woowacourse-teams/2026-pheeeew/issues/658)이 이 전환을 요구해요.

## Decision

그룹 프레스를 **그 그룹의 현재 멤버들이 그 주에 누른 개인 프레스의 합**으로 구해요. `device_region_daily_presses` 를 `group_members` 와 조인하고, 그룹에 직접 쌓는 경로(`POST`, `GET /api/v2/groups/{groupId}/presses`)를 제거해요.
**멤버십을 프레스 시점이 아니라 조회 시점에 평가해요.** 탈퇴하면 그 주 기록이 전부 빠지고 가입하면 전부 들어와요.
`group_daily_presses` 테이블과 기존 데이터는 남기고 읽기만 옮기며, 기존 데이터를 합산해 이전하지 않아요.

## Alternatives

- 개인 프레스 행에 `group_id` 를 비정규화 — 가입, 탈퇴 대칭성을 잃고 쓰기 시점에 속한 그룹 수만큼 행이 늘어나요.
- SQL `RANK()` 로 상세 전용 순위 쿼리를 만들기 — 공동 순위 규칙이 두 벌이 되어 상세와 랭킹이 어긋나도 테스트가 양쪽을 각각 통과해요.
- 기존 `group_daily_presses` 를 합산해 이전하기 — 두 원천의 집계 기준이 달라 어느 값이 맞는지 설명할 수 없어요.
- `POST` 를 deprecated 로 한 릴리스 유지하기 — 누를 수는 있는데 그룹 점수가 오르지 않는 상태가 생겨요.

## Consequences

- (+) 한 그룹의 행 하나를 모두가 다투는 천장이 사라져요. 이 전환의 목적이에요.
- (-) **위치 없이는 그룹에 기여할 수 없어요.** 서비스 범위 밖에서는 개인 프레스가 저장되지 않으므로 그룹 점수 기여도 0이에요. ADR-0028 의 거부 정책이 그룹 점수로 전파돼요.
- (-) **지난주 랭킹이 고정되지 않아요.** 멤버십을 조회 시점에 평가하므로, 지금 멤버가 바뀌면 지난주 순위도 다시 계산돼요.
- (-) 누가 그룹을 나가면 그룹 점수가 줄고 순위가 내려가요.
- (-) 기존 `group_daily_presses` 값이 상세와 랭킹에서 사라져요. 개발 서버에 쌓인 값이 있으면 프레스 개수가 줄어 보여요.
- (-) 상세 응답 하나를 만들 때 전 그룹 집계를 다시 두 번 돌아요. 공동 순위 규칙을 한 벌로 유지한 대가예요. ADR-0030 이 적은 "두 번에서 한 번으로 줄어요" 가 낡아요.
- (=) 기기가 N개 그룹에 속하면 한 번 누른 것이 N개 그룹에 모두 세어져요. 의도한 동작이라 집계에서 중복을 제거하지 않아요.
- (=) 프레스 랭킹의 이전 주 데이터 존재 판정이 전환 직후 `false` 가 돼요. 새 원천에 그 이전 기록이 없어요.
- (=) 상세 응답의 `weeklyScore`, `weeklyRank` 를 `weeklyStampCount`, `weeklyStampRank` 로 개명하고 `weeklyPressCount`, `weeklyPressRank` 를 더해요. 네 값이 공존하면 이름에 스탬프와 프레스가 드러나야 해요.
- (=) `pheeeew.group.press.*` 여섯 개가 더 이상 증가하지 않아요. 관측은 `pheeeew.emotion.press.*` 로 모여요.
- (=) ADR-0030 은 Accepted 를 유지해요. 멤버십 검사 제거, `inviteCode` 전체 노출, `GroupViewerRole` 은 그대로 유효해요. 다만 **그 Decision 이 제거한 세 필드 중 `weeklyPressRank` 가 같은 이름, 같은 타입으로 돌아오고** Consequences 두 줄이 낡아요. 결정 전체가 대체된 것은 아니므로 `Superseded by` 를 쓰지 않아요.
- 재검토: 개인 프레스 행이 늘어 조인 집계가 요구를 충족하지 못하면 롤업 테이블이나 비정규화를 다시 판단해요. 멤버 한 명인 그룹의 프레스 개수가 그 기기의 주간 총량과 같은 것은 #647(공개, 비공개 그룹)에서 다시 봐요.
