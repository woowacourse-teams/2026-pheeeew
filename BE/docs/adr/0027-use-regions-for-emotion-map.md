# ADR-0027: 넓은 지도에서 서버 행정구역 감정 집계를 사용한다

## Status

Accepted (2026-10-04). 승인된 BE 설계와 구현을 기록해요. 클라이언트 적용이나 운영 전환 완료를 뜻하지 않아요.
분류·신규 등록의 정상 미매칭 정책은 [ADR-0028](0028-assign-nearby-regions-and-restrict-emotion-creation.md)에서 부분 변경했어요. 집계·표시 계약은 유지해요.

## Context

- 기존 지도는 개별 감정을 200개씩 반환해요. 조사 당시 Android 호출자는 마지막 커서 페이지까지 결과를 누적했어요.
- 사용자가 제공한 iOS 실기기 지도 탭 캡처에는 CPU 63%, 메모리 441.1MB, 40 FPS와 Energy Impact `Very High`가 표시됐어요. 기기·빌드·데이터 규모·조작 조건은 미확인이며 원인이나 개선 효과를 증명하지 않아요.
- [이슈 #596](https://github.com/woowacourse-teams/2026-pheeeew/issues/596)은 선택한 지역 전체의 누적 개수와 대표 감정을 요구해요.

## Decision

넓은 지도에서는 원본 감정을 모두 받는 대신 서버가 지역 전체의 누적 개수와 대표 감정을 반환해요.
고정된 SGIS 2025년 2분기 경계를 내부 PostGIS에 저장하고, 감정의 최종 저장 Point를 행정동·읍·면 하나에 연결해 상위 지역을 합산해요.
화면 bbox는 경계 일부나 경계선이 교차하는 지역을 선택하는 데만 사용하며, 집계 대상에 다시 적용하지 않아요.

## Alternatives

- 클라이언트 클러스터링만 적용: 이미 받은 원본을 묶으므로 원본 수신·보관 부담과 지역 전체 누적 집계를 해결하지 못해요.
- 거리 기반 집계·사전 집계·캐시: 다른 집계 기준이나 동기화·운영 책임이 추가되므로 초기 범위에서 제외해요.

## Consequences

- (+) 화면마다 개별 감정의 모든 페이지를 누적하지 않고 지역 요약을 한 번에 받을 수 있어요.
- (-) 지역 전체 집계와 개인 감정·작성자 차단 제외 때문에 요약 개수는 화면의 개별 기록 수보다 클 수 있어요. 기존 개별 지도·상세의 차단 정책과 그룹 권한은 유지해요.
- (=) `regions`에 SGIS 코드·부모 관계, `MultiPolygon(4326)` 경계와 `ST_PointOnSurface`로 만든 고정 표시점을 저장해요. 원본 5179 경계는 `ST_Transform`으로 변환하며 감정·클라이언트 좌표계는 4326을 유지해요.
- (=) 분류는 `ST_Covers`와 코드 오름차순으로 하나를 선택해요. 정상 미매칭은 지역 코드가 null이어도 분류 시각을 남겨 미처리와 구분하고, 지역 요약에는 포함하지 않아요.
- (-) 고정 데이터셋의 코드를 참조하므로 경계 교체에는 별도 참조 전환·재분류가 필요해요. 정기 경계 갱신은 이번 범위에서 제외해요.

집계는 `NONE`, `MEMO`, `AUDIO`를 모두 포함하고 삭제·서비스 전체 비노출 기록과 조회 시점 이후 기록은 제외해요.
기간 하한 없이 같은 대상으로 개수와 대표 감정을 계산하며, 선택한 그룹의 공개 UUID 필터를 두 값에 함께 적용해요.
대표 감정 동률은 `ANGRY → DISCOURAGED → EXHAUSTED → FRUSTRATED → IRRITATED` 순서예요.
NULL 상태도 개수에 포함하고 모두 NULL이면 대표 감정은 null이에요. 0개 지역은 생략해요.

클라이언트가 `SIDO / SIGUNGU / EMD`와 기존 개별 지도 조회의 전환을 선택해요. 정확한 줌 기준은 미확정이에요.
`SIGUNGU`에서 수원·성남·용인 등은 각 구를 반환하며 별도 `CITY` 계층은 두지 않아요.
지역 API는 문자열 지역 ID를 가진 Feature의 최상위 배열을 반환하고 페이지네이션 래퍼를 사용하지 않아요.
클라이언트는 화면 안의 표시점만 렌더링하고 화면 밖 표시점은 보관하며, 현재 요청의 최신 성공 응답으로 목록을 교체해요.
세부 요청·응답과 표시 계약은 [클라이언트 연동 문서](../client/emotion-region-map.md)를 따라요.

재검토: 실제 경계 품질·조회 비용이 요구를 충족하지 않거나 지역 표시·갱신 정책이 바뀌면 다시 판단해요.

## Compliance

- PostgreSQL 17 / PostGIS 3.5 Testcontainers로 스키마·공간 조회·집계 정책과 기존 멱등성·녹음 원자성·수정·동시 백필 경계를 검증해요.
- 실제 SGIS 경계 적재·검증과 합성 자료의 로컬 SQL·HTTP 비교를 실행했어요. 합성 자료에서 요청 수·본문 바이트·반환 항목 수 감소를 관측했으며 운영 지연·처리량이나 실기기 CPU·메모리·프레임 개선을 확정하지 않아요. Grafana 응답 시간은 보조 근거로 구분해요.
- 경계 검증은 지정한 읍면동 14쌍의 쌍별 1㎡ 이하 겹침만 예외로 허용해요. 도형은 보정하지 않으며 동일·완전 포함 도형은 거부해요. 다른 원본에 예외를 그대로 적용하지 않아요.
- `region_datasets`의 경계·백필 검증 시각을 분리해요. 경계 미검증 상태의 신규 등록과, 두 검증이 완료되지 않은 지역 요약은 `EMOTION-013`·503으로 실패해요. 실패를 빈 목록으로 처리하지 않아요.
- 적재 SQL과 별도 경계 검증 SQL을 수동 실행해요. 백필 완료 검사는 구버전 등록 쓰기와 진행 중 등록을 종료한 뒤 실행해요. 개발·운영 적재·백필·배포는 아직 수행하지 않았으며 별도 승인이 필요해요. [실행 절차](../../scripts/regions/README.md)를 따라요.
