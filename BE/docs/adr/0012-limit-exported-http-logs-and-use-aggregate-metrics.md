# ADR-0012: 요청 통계는 지표로 집계하고 외부 전송 로그는 검토된 오류·느린 요청으로 제한한다

## Status

Proposed (2026-09-11)

현재 모니터링 브랜치의 수집 정책을 팀 검토를 위해 기록해요. 로컬 검증을 마쳤으며 실제 운영 전송량과 진단 효과는 아직 확인하지 않았어요.

## Context

- 클라이언트가 지도 화면을 움직일 때 조회를 반복하므로 요청량이 많아질 수 있어요. 모든 요청을 개별 로그로 남기면 처리·전송·보관량도 함께 늘어요.
- 요청량·오류 비율·응답 시간 분포는 집계 지표로 관찰할 수 있지만, 개별 장애를 조사하려면 요청을 연결할 번호와 오류 위치가 필요해요.
- 앱 로그 파일에는 직접 정의한 HTTP 로그와 라이브러리 로그가 함께 들어갈 수 있어요. 예외 메시지나 SQL 오류 원문에는 요청 내용·식별자 등 민감한 값이 포함될 수 있어요.
- 요청마다 달라지는 추적 번호나 좌표를 라벨로 사용하면 시계열·로그 스트림 수가 크게 늘어날 수 있어요.

## Decision

요청 빈도·오류·지연과 지도 조회 결과는 집계 지표로 관찰하고, 개별 HTTP 로그는 서버 오류(5xx)와 설정한 기준 이상의 느린 요청에 남겨요. 외부 전송은 앱이 직접 정의하고 검토한 HTTP 로거와 두 이벤트를 모두 만족하는 로그만 허용해요. 로그에는 경로 템플릿·상태 코드·처리 시간·추적 번호와 예외 종류·위치를 기록하며, 요청 원문·좌표·인증 정보·예외 메시지는 제외하고 추적 번호는 라벨로 사용하지 않아요.

## Alternatives

- 모든 요청을 개별 로그로 기록·전송 — 정상 요청까지 상세히 조사할 수 있지만 지도 요청량에 비례해 로그량이 늘고, 보관할 데이터와 노출 위험을 관리하는 부담이 커서 선택하지 않았어요.
- 앱 로그 파일 전체를 Cloud로 전송 — 라이브러리 진단 정보도 확보할 수 있지만 각 로그의 민감 정보 포함 여부를 검토하지 않은 상태라 선택하지 않았어요.
- 지표만 수집 — 전송량을 줄일 수 있지만 개별 오류의 추적 번호와 예외 위치를 확인하기 어려워 선택하지 않았어요.

## Consequences

- (+) 빈번한 정상 요청은 집계값으로 관찰하고, 조사할 필요가 높은 HTTP 요청의 로그를 Cloud에서 조회할 수 있어요.
- (+) 검토한 로그만 전송하고 변동이 큰 라벨을 제외해 외부 노출 범위와 시계열·스트림 증가를 제한해요.
- (-) 빠른 정상 응답과 빠르게 끝난 4xx 요청은 개별 HTTP 로그로 남기지 않아요. 예외 메시지와 라이브러리 로그도 Cloud에 없어 일부 원인 분석에는 추가 확인이 필요해요.
- (-) 집계 지표만으로 특정 요청 내부의 단계별 소요 시간을 재구성할 수는 없어요.
- (=) 로거·이벤트·필드가 바뀌면 전송 허용 규칙과 민감 정보 검토를 함께 갱신해야 해요. 이 정책은 로컬·콘솔에 남는 별도 라이브러리 로그까지 민감 정보 제외를 보장하지 않아요.
- 재검토: 제한된 로그로 반복 장애의 원인을 찾기 어렵거나 감사·추적 요구가 생기면 필요한 데이터, 마스킹·샘플링과 보관 정책을 검토한 뒤 수집 범위를 조정해요.

## Compliance

- 요청 로깅 테스트로 오류·느린 요청의 기록 조건과 민감 정보 제외를 확인하고, Alloy 로컬 검증으로 허용된 로거·이벤트만 전송되는지 확인했어요.
- HTTP 로깅의 처리 범위는 [ADR-0011](0011-use-servlet-filter-for-http-request-logging.md), 수집 구성과 허용 규칙은 [Alloy 연결 안내](../../docker/alloy/README.md)에서 확인해요.
