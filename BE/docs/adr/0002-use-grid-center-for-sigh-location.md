# ADR-0002: 격자 중심과 최종 표시 위치를 분리한다

## Status

Superseded by [ADR-0006](0006-use-independent-uniform-disks-for-sigh-location.md) (2026-09-07)

아래는 2026-08-31에 채택한 이전 계약과 판단 근거를 보존한 내용이에요. 새 계약의 구현과 구형 앱 전환 조건은 ADR-0006을 따라요.

## Context

- 한숨을 지도에 표시하려면 위치가 필요하지만 정확한 사용자 위치를 서버에 전달하거나 저장하지 않아야 해요.
- 클라이언트와 서버가 모두 무작위 좌표를 만들면 서버가 원래 격자를 다시 찾기 위한 좌표계·원점·경계 규칙까지 공유해야 해요.
- 등록 직후 상세 조회 API 없이도 클라이언트가 생성된 한숨 위치로 지도를 이동할 수 있어야 해요.
- 같은 등록 요청의 네트워크 재시도와 동시 요청은 한숨과 표시 위치를 중복 생성하지 않아야 해요.

## Decision

클라이언트는 WGS84 위치를 `EPSG:5179`로 변환하고 각 축에 `floor(value / 300) * 300 + 150`을 적용해 `300m × 300m` 격자의 중심만 서버에 전달해요. 클라이언트는 무작위 오프셋을 적용하지 않고 정확한 위치를 폐기해요.

서버는 받은 중심을 `EPSG:5179`로 변환하고 easting과 northing에 각각 `[-150m, 150m)`의 균등 무작위 오프셋을 최초 등록 시 한 번 적용해요. 결과를 WGS84 최종 표시 위치로 변환해 `geometry(Point, 4326)`에 저장하고, 요청 중심 원문은 저장하지 않아요.

`requestId`만으로 멱등성을 판별해요. 같은 `requestId`가 다시 오면 좌표를 새로 만들지 않고 최초 등록한 한숨과 최종 위치를 반환해요. 재시도 요청의 중심 좌표가 달라도 최초 결과를 반환하며, 서버는 클라이언트가 보낸 중심 원문을 저장하거나 비교하지 않아요. 등록 응답은 최종 위치를 `[longitude, latitude]` 순서의 GeoJSON `Feature`로 반환해요.

## Alternatives

- 클라이언트와 서버가 같은 격자 안에서 각각 무작위화 — 서버가 클라이언트의 격자를 다시 찾아야 하고 두 무작위화 단계가 추가 보호 효과를 설명하기 어려워 선택하지 않았어요.
- 정확한 위치를 서버에 보내고 서버만 무작위화 — 서버가 정확한 위치를 처리하게 되어 최소 수집 원칙에 맞지 않아 선택하지 않았어요.
- 격자 중심을 최종 표시 위치로 사용 — 구현은 단순하지만 같은 격자의 모든 핀이 겹쳐 선택하지 않았어요.
- 조회할 때마다 위치를 무작위화 — 지도 갱신마다 핀이 움직이고 멱등 응답을 만들기 어려워 선택하지 않았어요.
- `requestId`와 요청 중심 지문을 함께 비교 — 같은 `requestId`가 다른 중심과 함께 오면 오사용을 감지할 수 있지만, MVP 멱등성에 필요하지 않은 파생 값을 저장하고 충돌 계약을 추가해야 해 선택하지 않았어요.

## Consequences

- (+) 서버와 서버 로그가 정확한 사용자 위치를 받지 않아요.
- (+) 서버가 클라이언트의 격자 원점을 재현하지 않아도 요청 중심으로 최종 위치를 만들 수 있어요.
- (+) 저장된 최종 위치를 반환하므로 재시도와 이후 조회에서 핀이 움직이지 않아요.
- (-) 클라이언트가 `EPSG:5179` 변환과 축 순서를 정확히 구현해야 해요.
- (-) 실제 위치와 최종 표시 위치의 거리는 같은 격자의 대각선인 최대 약 `424m`가 될 수 있어요.
- (-) 클라이언트가 서로 다른 등록 시도에 `requestId`를 재사용하면 서버는 새 요청으로 구분하지 못하고 최초 결과를 반환해요.
- (=) 서로 다른 `requestId`로 같은 격자에 등록한 한숨은 서로 다른 최종 위치를 가질 수 있어요.
- 재검토: 격자 크기가 위치 보호나 지도 경험에 맞지 않거나 서비스 지역이 대한민국 밖으로 확장될 때 다시 판단해요.

## Compliance

- 클라이언트와 서버는 공통 WGS84 ↔ `EPSG:5179` 테스트 좌표로 축 순서와 격자 중심을 확인해요.
- 좌표 변환, 공간 저장과 동시 멱등 등록은 PostgreSQL 17과 PostGIS 3.5 환경에서 검증해요.
- 요청 본문, 정확한 위치와 클라이언트가 보낸 격자 중심을 애플리케이션 로그에 남기지 않아요.

클라이언트 계산식과 공통 테스트 좌표는 [클라이언트 300m 격자 중심 계산 가이드](../client/300m-grid-center.md)를 따라요.
