# ADR-0025: 한숨의 조회 기간 만료를 상세 재요청 시 판정한다

## Status

Accepted (2026-09-15)

## Context

- 한숨 조회 범위는 한국 시간(`Asia/Seoul`) 기준 오늘(0일)부터 13일 전까지 총 14일이에요. 목록만 제한하고 상세 조회는 허용하던 범위를 상세 조회까지 확장해요.
- 지도나 바텀 시트에 이미 전달한 한숨은 자정이 지나 조회 기간 밖이 되어도 화면에 남을 수 있어요. 서버의 다음 응답에서 제외하는 것만으로 이미 전달한 데이터를 회수할 수는 없어요.
- 바텀 시트 응답에는 메모도 포함돼요. 클라이언트가 이 데이터만으로 상세를 표시하면 서버가 만료 여부를 다시 판정할 요청이 없어요.
- 목록을 보고 있던 사용자의 스크롤을 자정에 끊지 않으면서, 기간이 지난 별을 선택했을 때는 일반 장애와 구분해 소멸을 안내하고 싶어요.

## Decision

- 지도와 목록은 매 요청의 현재 한국 날짜로 조회 시작일을 계산해요. 목록의 종료 시각은 최초 스냅샷을 유지하고, 다음 페이지에 남은 한숨이 없으면 `200`, 빈 `items`, `hasNext: false`, `nextCursor: null`을 반환해요.
- 클라이언트는 별을 선택하면 `GET /api/v2/sighs/{id}`로 상세를 재조회해요. 서버는 요청 시각을 한 번 읽고, `createdAt`이 현재 한국 날짜의 13일 전 자정보다 이르면 만료로 판정해요. 시작 경계와 같은 시각은 허용해요.
- 기기가 유효하지 않으면 기존 인증 오류를 반환해요. 없거나 삭제된 한숨은 기존 `404 / SIGH-002`를 반환하고, 삭제되지 않았지만 기간이 지난 한숨은 `410 Gone / SIGH-004`(`SIGH_EXPIRED`, `message: 한숨의 조회 기간이 지났습니다.`)로 구분해요.
- 클라이언트는 `SIGH-004`를 받으면 "별의 힘이 다해서 소멸했습니다"와 같은 안내를 표시하고 해당 별을 현재 화면과 목록에서 제거해요. 응답의 `message` 문구가 아닌 `code`로 분기하며, 네트워크 장애나 다른 오류를 소멸로 처리하지 않아요.
- 이 판정은 상세 조회에만 추가해요. 생성 시각이나 `deleted_at`을 변경하지 않으며, 등록 재요청의 멱등 응답과 좋아요·신고·차단 동작의 허용 범위는 변경하지 않아요.

## Alternatives

- 목록만 제한하고 상세는 계속 허용 — 이미 받은 ID로 기간이 지난 별을 계속 열 수 있어 소멸을 안내하려는 정책에 맞지 않아요.
- 자정에 커서를 거부하고 목록을 다시 조회 — 스크롤을 끊고 클라이언트에 목록 재시작 처리를 요구해요. 이미 전달한 항목을 그 자체로 회수하지도 못해요.
- 클라이언트 타이머만으로 만료 판정 — 화면에서 미리 제외할 수 있지만 기기 시각과 앱 실행 상태에 의존해요. 서버에서 상세 요청을 다시 확인하는 계약을 대신하지 않아요.
- `404`와 전용 만료 코드 — 코드로 구분할 수 있지만, 기간 종료로 더 이상 접근할 수 없다는 의미를 HTTP 상태에도 드러내기 위해 `410`을 선택했어요. [RFC 9110 §15.5.11](https://www.rfc-editor.org/rfc/rfc9110.html#section-15.5.11)은 접근이 더 이상 제공되지 않고 그 상태가 지속될 것으로 예상되는 경우를 설명해요.

## Consequences

- (+) 자정 이후에도 목록을 이어서 볼 수 있고, 기간이 지난 별을 선택했을 때는 장애와 구분되는 안내가 가능해요.
- (-) 이미 전달한 한숨은 상세 재요청이나 목록 갱신 전까지 화면에 남을 수 있어요. 이미 열어 둔 상세 화면을 자정에 강제로 닫거나 내용을 회수하지 않아요.
- (=) 클라이언트에 상세 재조회와 `SIGH-004` 처리 연동이 필요해요. 오프라인이거나 재요청이 없으면 서버가 최신 만료 상태를 알릴 수 없어요.
- (=) '소멸'은 조회 기간 만료를 나타내는 화면 표현이에요. 데이터는 유지하며 [ADR-0005의 소프트 삭제](0005-soft-delete-sigh.md)와 구분해요.
- 재검토: 상세 재요청 전에도 화면에서 즉시 숨겨야 하거나, 만료된 한숨의 다른 동작까지 제한해야 할 때 범위를 다시 정해요.

## Compliance

- 서버 통합 테스트로 시작 경계 포함, 경계 직전 만료, 한국 시간 자정 전후의 상세 응답 변화를 검증해요.
- 없거나 삭제된 한숨의 `404`, 기기 검증, 만료된 한숨의 등록 재요청 응답이 기존 계약을 유지하는지 확인해요.
- Controller 테스트와 OpenAPI에 `410 / SIGH-004` 응답을 명시하고, 클라이언트에서 소멸 안내와 항목 제거가 연결되는지 별도로 확인해요.
