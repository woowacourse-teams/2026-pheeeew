# ADR-0027: 그룹 감정 입력은 단일 API로 합산하고 요청별 처리 기록은 저장하지 않는다

## Status

Proposed (2026-09-28)

## Context

- 그룹 감정 버튼 API는 요청마다 한 번 누른 입력만 받아, 연타 시 그룹·멤버 확인과 집계 조회가 반복된다. 관련 이슈는 [#466](https://github.com/woowacourse-teams/2026-pheeeew/issues/466)이다.
- 감정 버튼 횟수는 그룹의 일별 집계이며 지도 감정이나 그룹 점수·순위에는 영향을 주지 않는다.
- 이번 범위는 단건과 여러 입력을 같은 형식으로 받는 것이다. 사용자는 요청별 중복 방지 기록 없이 처리하고, 통신 실패 시 일부 입력이 집계에서 빠질 수 있는 정책을 선택했다.

## Decision

`POST /api/v2/groups/{groupId}/presses`에서 `presses: [{state, count}]`를 받는다. 한 번 누른 경우에도 항목 하나에 `count: 1`을 보낸다. 항목은 1~5개, 양수 정수 횟수의 전체 합계는 최대 100회로 제한하고 같은 감정은 합산한다.

그룹 멤버를 확인한 뒤 기존 `group_daily_presses`에 감정별 증가량을 원자적으로 더한다. 여러 감정은 이름순으로 갱신하며 요청 전체를 한 트랜잭션으로 처리한다. 요청별 엔티티·테이블·해시·`requestId`는 추가하지 않는다.

## Alternatives

- 별도 `/presses/batch` API: 기존 단건 본문을 유지할 수 있지만 두 입력 계약을 관리해야 한다. 단일 API와 목록형 본문으로 통일한다.
- 요청별 중복 방지 기록: 응답 유실 뒤 안전하게 재시도할 수 있지만, 매 요청에 저장 비용과 기록의 보존 정책이 추가된다. 이번 범위에서는 보류한다.

## Consequences

- (+) 기존 집계 테이블만 사용하고 감정별 `+N`으로 처리한다. 요청 이력과 기기별 감정 기록을 새로 저장하지 않는다.
- (+) 동시 입력의 증가량과 묶음 전체의 성공·롤백은 DB 쿼리와 트랜잭션으로 보호한다.
- (-) 같은 본문을 다시 보내면 다시 증가한다. 클라이언트는 결과가 불분명한 입력을 자동 재전송하지 않고, 이후 그룹 상세 조회에서 서버 집계와 화면 숫자를 맞춘다. 이 정책은 일부 입력의 유실을 허용한다.
- (-) 기존 `{state}` 본문은 400이 된다. 클라이언트도 목록형 본문으로 함께 전환해야 한다.
- (=) 서버 처리 시점의 한국 날짜에 집계하며 그룹 멤버 권한, 지도 감정·순위 정책, 응답 구조는 유지한다. 클라이언트 수정과 배포는 이 BE 변경에 포함하지 않는다.
- 재검토: 통신 실패 후 안전한 재시도나 누른 횟수의 정확한 1회 반영이 요구될 때 중복 방지를 다시 설계한다.

## Compliance

- Controller 테스트에서 목록형 단건·다건, 같은 감정 합산, 입력 범위, 이전 본문 거절을 검증한다.
- PostgreSQL 17/PostGIS 3.5 통합 테스트에서 동시 합산, 중간 실패의 전체 롤백, 같은 본문의 반복 집계, 날짜·권한·순위 경계를 검증한다.
