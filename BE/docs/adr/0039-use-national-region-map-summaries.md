# ADR-0039: v2 시도·시군구 지도는 화면과 무관한 전국 요약을 반환한다

## Status

Accepted (2026-10-15). 사용자 승인에 따른 BE 구현 결정이며 앱 연동·운영 배포 완료를 뜻하지 않아요.
ADR-0027의 시도·시군구 지역 선택 방식만 변경해요. 기존 집계·분류·표시점 정책은 유지해요.

## Context

- 기존 v2 지역 지도는 요청마다 화면과 MultiPolygon의 교차를 검사한 뒤 선택된 지역 전체를 집계해요.
- 사용자는 시도·시군구 전국 요약을 받아 앱이 화면에 맞춰 표시하는 방향을 선택했어요.
- 현재 요청은 bbox와 계층을 필수로 받아요. 클라이언트는 EMD 요약을 요청하지 않지만 기존 요청 호환은 유지해요.

## Decision

`GET /api/v2/emotions/map/regions`에서 SIDO·SIGUNGU는 계층으로 지역 메타데이터를 읽고 전국을 집계해요.
bbox 파싱·범위 검증과 기존 필터·응답을 유지하되 두 계층의 지역 선택에는 bbox를 사용하지 않아요.
EMD는 기존 공간 조회를 유지해요. 별도 v3 경로, bbox 저장 컬럼, 서버 응답 캐시는 추가하지 않아요.

## Alternatives

- bbox 생성 컬럼으로 원본 경계 조회 최적화: 부분 교차에서는 정밀 판정이 남고 스키마 변경·잠금이 추가돼요.
- 별도 v3 API: 기존 요청을 유지하며 v2 내부만 전환하겠다는 사용자 결정으로 제외했어요.

## Consequences

- (+) SIDO·SIGUNGU 조회는 화면 크기·위치와 무관하며 원본 경계를 읽거나 공간 교차를 계산하지 않아요.
- (-) 기존 v2보다 화면 밖 지역이 더 많이 반환돼요. 앱은 현재 화면 안의 고정 표시점만 렌더링해야 해요.
- (=) 코드 정렬·0건 생략·기기/그룹 검증·날짜/내용/범위 필터와 경계·백필 준비 검사는 유지해요.
- (=) EMD 호환 요청은 여전히 공간 조회 비용이 있어요. 서버 캐시가 없으므로 매 요청마다 감정 집계는 실행돼요.
- (=) DB 스키마 변경·백필은 필요하지 않아요. 기존 공간 데이터·인덱스는 분류와 EMD 조회를 위해 유지해요.
- 재검토: 전국 응답 크기·집계 시간 또는 실제 앱 표시 비용이 문제가 될 때 다시 판단해요.

## Compliance

PostgreSQL 17/PostGIS 3.5 통합 테스트로 bbox에 무관한 결과·공간 조회 미사용·EMD 화면 선택을 검증해요.
HTTP 테스트로 기존 bbox 검증과 인증 기기·필터·응답·오류 계약을 보호해요. 운영 성능과 실기기 검증은 별도예요.
