# ADR-0043: 기간을 지정한 기본 지도 조회도 캐시를 사용한다

## Status

Accepted (2026-11-04, [#1091](https://github.com/woowacourse-teams/2026-pheeeew/issues/1091)). ADR-0040의 캐시 적용 범위를 기간 조회까지 넓혀요.
ADR-0040의 쓰기·재집계 직렬화, 등록 3초 지연, 수정·삭제 즉시 반영, SQL 대체 계약은 그대로 유지해요.
구현·테스트 검증은 완료했으며 배포·운영 지표 확인은 아직 하지 않았어요.

## Context

- 앱의 기본 지도 조회는 `scope=ALL`, `contentType=ALL`에 오늘(KST) 기준 최근 한 달 기간을 지정해요.
- ADR-0040은 기간 없는 조회만 캐시해서, 가장 많은 요청이 매번 `bypass_period`로 SQL을 실행했어요.
- 운영 최근 7일 기준 캐시 적중은 v4 핀 약 1.6%(109/6,885), 지역 요약 약 4.7%(13/275)였어요.
- 같은 기간 핀 후보는 535건, v4 지도 p95는 약 50ms였어요. 이번 변경의 1차 목적은 지연 단축보다 캐시 대상을 주 트래픽과 맞추는 거예요.
- 핀 후보는 이미 작성 시각을 포함하고 최신순으로 정렬돼 있어요. 반면 지역 집계는 전체 기간 누적값만 보관해서 기간 조건을 계산할 수 없었어요.

## Decision

`ALL/ALL` 조회는 기간 유무와 관계없이 SIDO·SIGUNGU 요약과 핀에 캐시를 사용해요.
핀은 기존 후보에서 기간 밖 후보를 건너뛰고, 시작일보다 오래된 후보를 만나면 탐색을 멈춰요.
지역 집계는 전체 누적값과 함께 `KST 날짜 × 시군구 × 감정 상태` 단위 개수를 보관하고, 기간 요약은 해당 날짜를 합산해요.
같은 기간의 합산 결과는 `(스냅샷 버전, 시작일, 종료일)`을 키로 Caffeine에 보관해요. 값에는 SIDO·SIGUNGU 요약을 함께 담아요.
스냅샷이 바뀌면 버전도 바뀌므로 이전 결과를 명시적으로 무효화하지 않아도 다시 사용하지 않아요.

## Alternatives

- 기간 조회도 SQL 유지: 정합성 범위는 가장 작지만, 캐시가 주 트래픽에 거의 적용되지 않는 구조가 남아요.
- 기간별 결과만 캐시하고 날짜별 집계 없이 SQL로 채우기: 쓰기마다 모든 기간 결과를 무효화하고 다시 SQL을 실행해야 해서 반복 비용이 남아요.
- 결과 캐시 키에 지역 계층 포함: 로컬 비교에서 시도·시군구를 번갈아 조회하면 계산 횟수가 최대 2배였어요. 시도만 조회할 때의 메모리 절약은 64개 항목 기준으로 작아서 선택하지 않았어요.
- MEMO·AUDIO·MY·GROUP 필터까지 함께 확장: 집계 차원과 검증 범위가 커져서 요청 비중을 측정한 뒤 별도로 판단해요.
- 앱 내부 큐·Outbox·Redis·Elasticsearch: ADR-0040의 단일 JVM 전제 안에서는 동기화 문제를 줄이지 못하고 운영 비용이 커서 이번 범위에서 제외해요.

## Consequences

- (+) 앱 기본 한 달 조회가 캐시 경로를 사용하며, 같은 기간의 반복 요약 계산이 줄어요.
- (+) Caffeine 표준 지표(`cache="map_region_periods"`)로 기간 결과의 적중률을 관측할 수 있어요.
- (-) 재생성 SQL의 결과 행이 작성일 수만큼 늘고, 10분 정기 보정은 이 쿼리를 쓰기 잠금 안에서 실행해요.
- (-) 쓰기마다 날짜별 맵을 복사해요. 날짜 수가 늘면 잠금 안의 갱신 비용이 커져요.
- (-) 쓰기가 잦으면 스냅샷 버전이 자주 바뀌어 기간 결과 적중률이 떨어져요.
- (=) `bypass_period` 결정 값은 더 이상 기록하지 않지만 과거 시계열 해석을 위해 남겨요.
- 재검토: 재생성 시간·쓰기 잠금 대기·기간 결과 적중률·힙 사용량이 늘거나, MEMO·AUDIO·MY 요청 비중이 커질 때.

## Compliance

PostgreSQL 17/PostGIS 3.5에서 KST 날짜 경계, 같은 기간 결과 재사용과 삭제 후 재계산, 등록 1초 배치 반영, 기간 핀 선택, 비기본 필터 우회를 검증해요.
날짜별 합산과 작성일 기준 변경 반영은 지역 집계 단위 테스트로 확인해요.
