# ADR-0033: 그룹 가입 방식을 공개, 비공개로 구분하고 생략을 비공개로 읽는다

## Status

Accepted (2026-10-09)

## Context

- 그룹에 가입하는 길은 초대 코드뿐이에요(`POST /api/v2/groups/join`). 코드를 모르면 어느 그룹에도 들어갈 수 없어요.
- [이슈 #647](https://github.com/woowacourse-teams/2026-pheeeew/issues/647)이 전체 그룹 탐색과 코드 없는 가입을 요구하고, [이슈 #668](https://github.com/woowacourse-teams/2026-pheeeew/issues/668)이 그중 가입 방식을 다뤄요.
- 배포된 앱은 생성 요청에 가입 방식을 보내지 않아요(`GroupCreateRequestDto` 는 `name`, `description`, `stamp` 뿐이에요). 서버가 생략을 어떻게 읽을지 정해야 해요.
- ADR-0030이 `inviteCode` 노출 범위 재검토를 **#647 착수 시점으로 예약**했어요.
- ADR-0032가 "기존 응답에 필드만 더하기" 를 기각했어요. 근거는 *"모르는 키를 거부하는 클라이언트를 깨뜨릴 수 있고, 그 위험을 서버에서 확인할 수 없어요"* 였어요.

## Decision

`groups.join_type` 을 `VARCHAR(20)` 문자열 enum 으로 두고 공개, 비공개를 구분하며, **공개, 비공개는 가입 방식만 가르고 노출 범위는 가르지 않아요.** 생략과 기존 행은 비공개로 읽어요 — 구버전 앱이 만든 그룹이 코드 없이 열리는 것보다 안전한 쪽이에요. ADR-0030이 예약한 재검토는 여기서 닫고 `inviteCode` 전원 공개를 유지해요.

## Alternatives

- `BOOLEAN is_public` — 저장소의 `BOOLEAN` 컬럼 두 개(`emotions.anonymous`, `app_version.is_active`)는 모두 이름 없는 플래그이고, 이름 있는 닫힌 집합은 전부 문자열 enum(`frame`, `state`, `level`, `role`)이에요. 값을 더할 때 `BOOLEAN` 은 배포된 필드의 호환 불가 변경이 돼요.
- 생략을 공개로 읽기 — 구버전 앱으로 만든 그룹이 코드 없이 열려요.
- 가입 방식을 새 버전 경로로 분리 — 배포된 앱이 가입 방식을 보내지 않으므로 생략 기본값이 어차피 필요하고, 경로만 늘어나요.
- 비가입자 응답에서 `inviteCode` 를 빼기 — ADR-0030이 예약한 대안이에요. 비공개 그룹의 코드를 가리는 것은 이번 범위가 아니라서 그대로 두었어요.

## Consequences

- (+) 공개 그룹을 코드 없이 열 수 있는 바탕이 생겨요. 비공개 그룹의 기존 입구는 그대로예요.
- (-) **`join_type = 'PRIVATE'` 은 "생략해서 비공개" 와 "비공개를 골라서 비공개" 를 구분하지 않아요.** 생략 관용을 언제 걷어낼 수 있는지 저장된 값으로는 판정할 수 없어요.
- (-) 구버전 앱에는 코드 없는 가입 화면이 없어, 공개 그룹을 만들어도 앱이 업데이트될 때까지 공개의 이점이 보이지 않아요.
- (-) `inviteCode` 를 계속 모두에게 보여주므로, 비공개 그룹의 코드도 상세를 열면 읽혀요. ADR-0030이 감수한 것을 그대로 감수해요.
- (=) **ADR-0032가 기각한 "기존 응답에 필드만 더하기" 를 이번에는 채택해요.** 기각 근거가 "서버에서 확인할 수 없다" 였고, 배포된 앱의 `ApiClient` 가 `ignoreUnknownKeys = true` 인 것을 확인해 그 근거를 닫았어요. **확인 대상은 `an/dev` 의 현재 코드이고 스토어 배포본이 아니에요.** ADR-0032의 바이트 보존 경계는 `GroupDetailResponse` 로 남겨 두었어요.
- (=) 비공개 그룹에 코드 없이 가입하려 하면 `GROUP-009` 409로 거절해요. 막는 것이 요청자의 자격이 아니라 그룹의 상태이고, 같은 엔드포인트의 `GROUP-007`도 409예요.
- (=) 마이그레이션의 `DEFAULT 'PRIVATE'` 는 전환 기간용이 아니라 **영구**예요. 롤링 배포와 롤백에서 구버전 서버가 `join_type` 없이 INSERT 하므로, 지우면 그 INSERT 가 실패해요.
- 재검토: **최소 지원 앱 버전이 가입 방식을 보내는 버전 이상으로 올라가면** 생성 요청의 생략 관용을 걷어내요. 비공개 그룹의 `inviteCode` 노출을 좁히는 날에는 `GROUP-009` 의 상태 코드를 함께 다시 판단해요.

## Compliance

- 생략이 비공개로 저장되는지는 컨트롤러 슬라이스와 영속 통합 테스트가 고정해요.
- 비공개 거절이 `GROUP-007`보다 먼저 판정되는지는 `GroupMembershipIntegrationTest` 가 고정해요. 공개 여부 검사를 저장 뒤로 옮기면 그 테스트 하나가 깨져요.
