# ADR-0036: 운영 서버 API를 Cloudflare 프록시 없이 직접 받는다

## Status

Proposed (2026-10-12)

개발 서버에 먼저 적용한 구성(ADR-0035)을 운영에 옮기는 제안이에요. 저장소 설정은 바꿨고, 운영 배포와 프록시 끄기는 아직 하지 않았어요.

## Context

- ADR-0035로 개발 서버 API의 프록시를 끄고 nginx가 Let's Encrypt 인증서로 직접 받게 했어요. 운영 적용은 그 결과를 보고 정하기로 했어요.
- 개발 서버에서 한 회선으로 5회씩 잰 값이에요. 새 연결의 요청은 0.31~0.53초에서 0.04~0.13초로, 연결을 재사용한 요청은 0.08초에서 0.015초로 줄었어요.
- 운영 API도 같은 날 측정에서 회선에 따라 홍콩(HKG) 또는 도쿄(NRT) 거점을 거쳤어요.
- 운영 nginx는 개발 서버가 바꾸기 전과 같은 구성이었어요. 요청 제한 3개 경로(기기 등록, challenge 발급, 그룹 참여)가 `CF-Connecting-IP` 헤더를 기준으로 해요.
- 운영은 스웨거가 앱 설정과 nginx에서 꺼져 있어 문서용 주소가 필요하지 않아요.
- 앱의 최소 지원 버전은 안드로이드 8.0, iOS 15.0이고 인증서를 고정하지 않아요.
- Cloudflare 대역에서 온 연결이라도 Cloudflare Workers가 `CF-Connecting-IP` 헤더를 임의로 넣을 수 있어요. [Cloudflare 문서](https://developers.cloudflare.com/fundamentals/reference/http-headers/)에 적힌 동작이에요.

## Decision

운영 서버의 API 주소도 Cloudflare 프록시를 끄고 nginx가 Let's Encrypt 인증서로 직접 받아요. 요청자 주소와 요청 제한의 기준은 연결 주소만 쓰고 `CF-Connecting-IP` 헤더는 믿지 않아요.

## Alternatives

- 운영은 프록시 유지 — 공격 방어를 그대로 쓰지만 요청마다 해외 거점을 왕복하는 지연이 실제 사용자에게 남아요.
- Cloudflare 대역에서 온 연결의 `CF-Connecting-IP` 신뢰 — 프록시가 켜진 동안에도 사용자별로 요청 제한을 셀 수 있지만 Workers로 헤더를 꾸며 제한을 우회할 수 있어 선택하지 않았어요.

## Consequences

- (+) 실제 사용자의 API 요청이 해외 거점을 거치지 않아요. 운영에서 줄어드는 시간은 전환 뒤에 재요.
- (+) 새 설정은 프록시가 켜져 있어도 동작해요. 문제가 생기면 DNS 프록시를 다시 켜서 요청을 Cloudflare 경유로 돌려요.
- (-) 프록시가 켜진 동안에는 요청 제한이 Cloudflare 거점의 주소로 세어져 같은 거점의 사용자들이 한 사람처럼 묶여요. 전환 중과 되돌린 상태에 해당해요.
- (-) 프록시를 다시 켜도 서버는 직접 붙는 요청을 계속 받아요. 완전히 되돌리려면 nginx 설정을 되돌리거나 보안 그룹에서 443을 Cloudflare 대역만 허용해야 해요.
- (-) 운영 서버의 IP가 공개되고 Cloudflare의 공격 방어와 봇 차단을 쓰지 못해요. nginx의 요청 제한은 3개 경로뿐이라 대량 요청은 서버가 직접 받아요.
- (-) 인증서를 90일마다 갱신해야 해요. 갱신이 실패하면 실제 사용자의 모든 요청이 실패해요.
- (=) DNS 편집 권한을 가진 Cloudflare API 토큰이 운영 서버에도 남아요. 토큰은 nginx 컨테이너에 연결하는 경로 밖에 둬요. 인증서 만료 알림을 따로 둬야 해요.
- 재검토: 직접 받은 뒤 공격이나 비정상 요청이 늘거나, 인증서 갱신이 실패한 적이 생기거나, 운영에서 잰 응답 시간 차이가 작으면 다시 판단해요.

## Compliance

- 임시 컨테이너에서 직접 연결과 Cloudflare 대역 양쪽에서 `CF-Connecting-IP` 가 무시되는 것, 헤더를 바꿔 가며 보낸 요청이 요청 제한에 걸리는 것, 스웨거와 Actuator 404, 토큰 파일이 컨테이너에서 보이지 않는 것을 확인했어요. 임시 인증서와 흉내 낸 앱으로 한 확인이에요.
- 실제 인증서에서의 동작과 전환 전후 응답 시간은 운영 배포 뒤에 확인해요.
- 발급, 갱신, 전환, 되돌리기 절차는 [nginx 안내](../../docker/nginx/README.md)에서 관리해요.
