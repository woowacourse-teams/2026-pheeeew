# E001 평가 재설계 초안

상태: **방향 승인 후 v2 사전등록 구체화**예요. 2026-09-06 사용자가 “좋아 구체화하고 바로 진행해줘”라고 요청했어요. 아래 내용은 승인 전 검토 이력으로 보존하고, 구체적인 평가 계약과 작업 순서는 [E001-v2 사전등록](PROTOCOL-V2.md)을 따라요. 이번 단위는 문서이며, runner 변경·실제 재실행·모델 채택은 아직 하지 않았어요.

## 무엇을 고치나요?

**별을 찍는 방식이 아니라, 찍힌 별을 평가하는 방법부터 고쳐요.**

현재 그림의 2·3번인 D 후보를 버리거나 합격 처리하지 않아요. 빈 테두리 구간에 보정값을 넣어 나쁜 점수를 만든 문제를 해결한 뒤, 더 자연스러운 군집을 목표로 한 E까지 공정하게 비교할 수 있게 설계해요.

v1 원본과 `inconclusive / no-d` 결과는 [결과 기록](results/2026-09-06-e001-v1/README.md)에 그대로 남겨요. 결과 기록 커밋은 `50183e1`이에요.

| 질문 | 제안하는 확인 방법 | 이 확인만으로 알 수 없는 것 |
| --- | --- | --- |

### 빈 테두리는 숫자로 만들어 탈락시키지 않아요

바깥 띠 `O`, 바로 안쪽 띠 `I`, 전체 개수 `N`을 각각 기록하는 방향이에요. 띠 위치는 일단 v1과 같은 경계 거리 0~30m, 30~60m를 검토 출발점으로 삼아요.

- `O=0, I=0`: 두 띠에서 관측한 별이 없다고 기록해요. 밀도비 점수는 만들지 않아요. 자동 합격이나 자동 탈락의 근거로 쓰지 않아요.
- `O>0, I=0`: 바깥 띠에서만 별이 관측됐다고 구분해요. 이 상태를 빈 띠와 똑같이 처리하지 않아요.
- `I>0`: 두 띠의 면적당 밀도비를 계산할 수 있지만, 실제 개수도 함께 봐요. 안쪽 별 한 개로 얻은 비율을 충분한 자료로 취급하지 않아요.

별도로 `O/N`은 관측된 바깥 띠 점유율로 기록할 수 있어요. 이것도 단독으로 “사각형이나 원형이 안 보인다”를 증명하는 점수는 아니에요.

**추천 방향은 기존 밀도비를 단독 탈락 기준에서 내려 보조 자료로 쓰는 것**이에요. 대신 거리 안전성, 바깥 점유율과 표본의 충분성, 반복 무늬, 시각 평가의 역할을 분리해요. “판단 자료 부족”을 전체 선택 흐름에서 어떻게 처리할지는 v2에서 명시적으로 정해야 해요. 단순히 v1의 `undefined`에 넣으면 기존 fail-closed 규칙 때문에 다시 자동 탈락하므로 지표만 바꿔서는 안 돼요.

## 바꾸지 않는 범위

- 클라이언트의 300m 격자 중심, 실험 후보의 최대 반경 300m, 생성 시 한 번 정하는 위치 계약을 유지해요.
- D의 두 σ 후보와 E의 좌표 생성 알고리즘은 이번 평가 재설계에서 바꾸지 않는 방향이에요.
- v1의 결과·프로토콜·checksum은 수정하지 않아요. 새 평가로 같은 표본을 다시 채점해 v1 합격으로 표시하지 않아요.
- 새 실험의 표본·seed·holdout·판정 기준은 실행과 그림 확인 전에 고정해요. v1 그림은 이미 본 사후 진단 자료로 구분해요.

## 승인 전 열어 두었던 질문

1. 바깥 점유율의 허용 수준과 표본 부족 처리 방법을 정해요. 이번 두 D 후보가 통과하도록 숫자를 역으로 맞추지 않아요.
2. 고정된 별 개수에서 빈 구간·소수 관측·명확한 경계 집중을 구분하는 검증 예제를 먼저 정해요. 균등 원처럼 원형 경계가 있는 대조군도 검사해요.
3. D를 기준으로 E를 비교하는 진입 조건과 최종 채택 조건을 정해요. 경계 자료 부족을 합격으로 숨기거나 모든 비교를 무조건 중단하지 않도록 각 결과 상태를 명시해요.

## 구체화한 답

바깥 점유율에는 새로운 합격선을 만들지 않아요. 개수·점유율·보정 없는 밀도비는 관측 상태를 설명하는 자료로만 기록하고, 생성 무결성·거리 제한과 분리해요. 빈 띠도, 한두 개 관측으로 얻은 밀도비도 자연스러움의 합격 증거가 아니에요.

D*는 E와 비교할 기준 후보일 뿐이에요. E가 탈락해도 D를 자동 채택하지 않고 현재 A와 D를 비교하는 블라인드 평가를 거쳐요. E가 수치·성능 조건까지 통과하면 D와 E의 블라인드 비교도 함께 진행해요. 추천 결과와 제품 채택은 계속 구분해요.

v1의 결과·합격선은 그대로 두고, v2의 새 seed·합성 중심·출력 경로를 고정했어요. **사전등록 → 지표·선택 흐름 → 산출물·평가 실행기 → 커밋 후 실험** 순서로 진행하며, 각 단위의 검증 후 커밋 전에 멈춰요. 세부 조건과 검증 예제는 [E001-v2 사전등록](PROTOCOL-V2.md)에 있어요.
