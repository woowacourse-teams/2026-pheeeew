# E006 가상 중심 탐색 비교

2026-09-07 사용자가 E001 결과 커밋 후 가상 중심 방식을 실제로 검증하고 비교 그림을 보여 달라고 요청했어요. E001의 판정·원본을 변경하지 않는 별도 탐색 실험이에요. 제품 코드·클라이언트 위치 계약·DB는 바꾸지 않아요. 독립 블라인드 평가나 모델 채택 시험이 아니에요.

## 실행 전에 고정한 비교

| 표시 | 정의 | 원래 격자 중심으로부터 범위 |
| --- | --- | --- |
| D | E001의 σ=120m tapered Gaussian 그대로 | r<300m |
| V | 매 별마다 Ux,Uy를 각각 [-150,150)m에서 독립 추첨하고 D 오프셋을 더해요. | r<300+150√2≈512.13m |
| V300 | V의 **합산 좌표**에 E001의 T(r/300)를 수락 확률로 적용해요. 거절되면 U와 D를 모두 다시 뽑아요. | r<300m |

V는 제안한 두 단계 이동 자체를 확인하는 진단용이며 현재 반경 계약을 만족하는 후보가 아니에요. V300은 비교를 위해 추가한 별도의 경계 보정 모델이에요. 경계 clamp나 V 좌표의 단순 축소를 사용하지 않아요. 세 방식 모두 실제 사용자 위치를 입력으로 사용하지 않아요. 범위가 같아도 p95가 다를 수 있으므로 자연스러움 개선을 중심 분산 하나의 인과 효과로 단정하지 않아요.

## 표본·그림·측정

- 상대 좌표 (0,0) 단일 중심과 300m 간격 3×3 균등·불균형 중심, 중심당 기준 500·5,000개를 비교해요. 불균형 가중치는 행 우선 (3,1,1,0.5,1.5,0.5,0.5,0.5,0.5), 합 9예요.
- seed는 2026090701~2026090705예요. 그림은 다섯 seed의 표본을 합쳐요. 모든 그림의 세 열은 각각 동일 총수예요. 실행당 313,500개(모델당 104,500개), 두 번 생성해 좌표·지표·PNG checksum 일치를 검사해요. D와 V의 첫 D 오프셋은 같은 난수열을 쓰고 U·수락 난수열은 분리해요. V300은 재추첨으로 이후 좌표가 달라져요.
- Java2D 정적 산점도 PNG를 생성해요. 상대 x/y는 m, 모든 패널 범위는 [-900,900]m로 같고 패널은 1200×1200px예요. V의 최대 범위까지 포함해 잘리는 점이 없어야 해요. 열 순서는 D / V / V300, 별은 기존 E001 sprite를 같은 6px 크기로 표시해요. 배경은 기존 어두운 지도 표현, 별은 같은 금색이며 열 제목으로 모델을 구분해요. E001 그림과 viewport·픽셀 크기가 달라 이번 세 열끼리 비교해요.
- 원본 CSV에 모델·조건·seed·중심·point index·최종 좌표·반경·합산 후보 횟수를 남겨요. seed별·pooled 반경 p50/p95/p99/max, r≥300 비율, 300m 주기의 경험적 푸리에 진폭, 단일 중심 각도 4차 성분을 기록해요. 푸리에 진폭은 |mean(exp(i2πx/300))|와 y축 값의 평균이며 0~1이에요. 이전 E001 grid300 지표와 다르고 절대 합격선·유의성 검정으로 쓰지 않아요.
- 그림의 질문은 ‘중심을 추가 분산하면 반복 무늬와 빈 공간이 어떻게 달라지는가’예요. 예상은 V의 반복 감소·거리 증가이고 V300 결과는 미정이에요. 결과를 본 뒤 seed·파라미터·축척을 골라 바꾸지 않아요. CPU 성능·DB·실제 앱 렌더링 성능을 측정하지 않아요.

## 재현 명령

BE에서 Java 21로 실행해요. 첫 명령은 가까운 자동 검증만 실행하고, 두 번째가 실제 탐색 실험이에요. 두 번째 명령의 대상 디렉터리가 이미 있으면 덮어쓰지 않고 중단해요. 재현할 때는 새 경로를 지정해요.

