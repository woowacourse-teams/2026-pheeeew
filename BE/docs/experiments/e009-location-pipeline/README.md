# E009 실제 위치·클라이언트 랜덤·기존 D 비교

2026-09-07 사용자가 요청한 세 경로를 합성 좌표 평면에서 비교해요. 제품 API·클라이언트·DB·ADR·위치 수집 정책은 변경하지 않아요. 기존 미커밋 E006/E007/E008도 보존해요.

## 실행 전 고정한 조건

| 열 | 클라이언트가 전송하는 좌표 | 서버에서 하는 계산 | 최종 분포 |
| --- | --- | --- | --- |
| 1 실제 위치 전송 | 합성 실제 위치 | 반경 300m 균등 원 내부 샘플링 | 실제 위치 중심의 균등 원 |
| 2 클라이언트 랜덤 전송 | 실제 위치 주변 반경 300m 균등 원에서 고른 좌표 | 받은 좌표 주변 반경 300m 균등 원에서 다시 샘플링 | 독립적인 원 오프셋 두 개의 합 |
| 3 기존 격자 기반 D | 300m 격자 중심 | 기존 tapered Gaussian σ120m, R300m | E007 D 좌표 그대로 |

‘기존’은 최근 비교한 D를 뜻해요. 최초 사각형 균등 샘플러와 다르며 현행 제품이 D로 바뀌었다는 뜻은 아니에요. 2번은 사용자의 정정에 따라 **클라이언트와 서버 모두 랜덤화**해요. 클라이언트의 첫 반경은 아직 별도로 지정되지 않아 300m로 가정하고 사용자에게 알렸어요. 원의 둘레가 아니라 **면적 전체에 균등**하게 뽑아요. r=300√U, θ=2πV, U/V는 독립 균등 [0,1)이에요.

1과 2의 **서버 오프셋** U/V를 이벤트별로 같게 맞추고 2번의 클라이언트 오프셋은 독립 seed에서 뽑아요. 최종 좌표는 같지 않아야 해요. 1은 실제 위치 기준 최대 300m, 2는 최대 600m예요. 2의 분포는 두 균등 원의 합성곱이라 단일 위치의 외곽 밀도가 더 부드럽게 줄어들 것으로 예상해요. 동시에 RMS 거리도 1의 300/√2≈212.1m에서 2의 300m로 커져요. 부드러움과 더 넓은 퍼짐이 함께 변하므로 동일 오차·동일 보호 수준의 비교는 아니에요. 자연스러움의 선호·승자는 미정이에요.

## 입력과 그림 계약

E007 raw/coordinates.csv.gz의 D행만 읽고 실제 위치·격자 중심·D 최종 좌표를 재사용해요. stationary-5000(같은 지점 반복), hotspots-4500, hotspots-45000, uniform-45000 네 장면에서 총 99,500개 이벤트, 출력은 세 경로 합계 298,500행이에요. 입력 seed 2026090701~2026090705는 유지해요. 각 이벤트의 원 샘플 seed는 SHA-256("e009|server|scene|seed|index")와 SHA-256("e009|client|scene|seed|index")의 첫 8바이트 big-endian long이며 각각 SplittableRandom 첫 두 double을 U/V로 사용해요. 재현용 난수이지 배포용 프라이버시 구현은 아니에요.

세 열 산점도 PNG 4장, 3264×1280px, 패널 1000×1000px, x/y ±1200m를 모든 장면에서 고정해요. 별 6px와 E001 금색 RGBA sprite·어두운 배경을 재사용해요. 모든 별의 생성 시간을 기준시각 2026-09-07T00:00:00Z, 관측 나이를 0h로 고정해 alpha=1이에요. E008의 실험용 24h 수명을 변경하지 않으며 이번에는 위치만 비교하므로 나이별 색상·감쇠·줌은 바꾸지 않아요. 실지도·기기 성능 결과가 아니에요. 원 테두리를 인위적으로 그리지 않아요.

숫자 1/2/3과 직접 제목으로 구분하고 동일한 금색을 사용해요. 질문은 전송·계산 경로와 격자 기반 D의 최종 분포 차이예요. 단위는 m이고 한 점은 합성 한숨 이벤트예요. 1/2와 3은 중심뿐 아니라 분포와 RMS 오차도 다르므로 순수 격자 제거 효과나 동등한 프라이버시 비교로 해석하지 않아요. D의 300m는 격자 중심 기준이고, 2의 각 단계 300m는 직전 단계 좌표 기준이에요.
